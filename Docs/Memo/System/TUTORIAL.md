# TUTORIAL / GUIDE

## PURPOSE

공용 대화 시스템과 Day 1 핵심 튜토리얼부터 Day 2~7 순차 가이드, 첫 주간 결산 이후 가계부와 직원 안내까지 초반 가이드의 확정 규칙과 구현·검증 상태를 관리한다.

* 정비 전체 밸런스 / 정비 가격표 / 업적 전체 보상표처럼 담당 시스템에서 별도로 확정할 내용은 이 문서에서 관리하지 않는다.
* 실제 게임 규칙과 상태는 기존 담당 Model을 원본으로 사용하며 튜토리얼은 진행 단계 / 표시 여부 / 입력 제한 / 강조 연출만 관리한다.

## CONFIRMED

### 전체 규칙

- Day 1은 핵심 플레이 루프를 끝까지 1회 완주하는 강제형 튜토리얼로 구성한다.
- Day 1 핵심 루프 완료 시 `CoreTutorialCompleted = true`.
- `CoreTutorialCompleted` 이후 Normal 주문을 해금한다.
- Day 2~7은 강제 튜토리얼이 아니라 순차 가이드로 처리한다.
- 첫 주간 결산 이후 가계부 / 직원 안내까지 완료하면 `AllGuidesCompleted = true`.
- Day 2~7 가이드는 `최초 등장 가능 시점 + 실제 상황 트리거`를 혼합한다.
- Day 4 정비 소개는 정비 상품 / 정비 화면까지 유도하되 실제 구매는 강제하지 않는다.
- Day 1 동안 정비 / 카탈로그 / 업적 등 아직 배우지 않은 사이드 액션은 잠근다.
- 설정은 접근성을 위해 Day 1에도 열어둘 수 있다.
- 튜토리얼 중 저장 / 종료 후 재접속하면 저장된 진행 단계부터 재개한다.
- 이미 실제 게임 상태에서 완료된 행동은 재접속 시 검사해서 자동 스킵한다.
- Day 1 주문은 랜덤 일반 주문이 아니라 튜토리얼 전용 고정 주문 데이터 1건을 사용한다.
- 현재 실행 중인 Day 1 핵심 튜토리얼 또는 후속 가이드는 튜토리얼 뷰의 스킵 버튼으로 종료할 수 있다.
- 스킵은 현재 안내만 완료하며 구매 / 재고 / 제작 / 배송 / 결산 같은 실제 게임 상태를 대신 변경하지 않는다.
- 캐릭터 대화는 튜토리얼 내부 기능으로 만들지 않고 인트로 / 튜토리얼 / 결산 이벤트 / 엔딩에서 재사용할 수 있는 공용 대화 시스템으로 구현한다.
- 공용 대화 시스템은 대사와 연출 신호만 전달하며 자금 / 주문 / 인벤토리 / 튜토리얼 상태를 직접 변경하지 않는다.
- 대화 결과에 따른 게임 상태 변경은 신호를 받은 담당 Presenter 또는 Scene Handler가 기존 Model 규칙을 통해 처리한다.
- 대화 재생 중인 줄 번호는 저장하지 않고 튜토리얼 단계를 저장한다. 재접속 시 해당 단계의 대화를 처음부터 다시 재생한다.

## DIALOGUE_SYSTEM

### 목적과 범위

공용 대화 시스템은 캐릭터 대사와 이미지 연출을 재생하고 완료 / 건너뛰기 / 연출 신호를 외부에 전달한다. 튜토리얼은 대화 시스템을 사용하지만 대화 시스템은 튜토리얼 진행 규칙을 알지 않는다.

#### MVP 지원 범위

- 화자 이름 / 본문 / 캐릭터 이미지 / 이미지 표시 방향
- 글자별 출력 / 출력 중 입력 시 현재 문장 즉시 완성 / 다음 입력 시 다음 대사 진행
- 대화 전체 건너뛰기 허용 여부
- 대화 종료 이벤트
- 지정된 시점의 연출 신호 전달
- 인트로 배경 이미지 교체 연결

#### MVP 제외 범위

- 선택지와 분기 대화
- 호감도와 복잡한 조건식
- 대화 시스템의 자금 / 아이템 / 플래그 직접 변경
- 대화 재생 중인 줄 단위 저장과 복구

### MVP 책임

- `DialogueData`: 대화 ID / 대사 목록 / 건너뛰기 허용 여부 / 종료 결과 ID를 보관한다.
- `DialogueLine`: 화자 / 본문 / 캐릭터 이미지 / 표시 방향 / 연출 신호를 보관한다.
- `DialoguePresenter`: 대화 시작 / 현재 문장 완성 / 다음 줄 / 건너뛰기 / 종료를 중재하고 완료와 연출 신호를 전달한다.
- `DialogueView`: 이름 / 본문 / 캐릭터 이미지 / 다음 표시 / 글자별 출력 / 열기와 닫기 연출을 담당한다.
- `TutorialPresenter`: 대화 완료와 연출 신호를 받아 행동 유도 단계를 진행하고 실제 Model 상태를 확인한다.
- `TutorialView`: 대화 본문을 소유하지 않고 화살표 / 대상 강조 / 입력 차단만 담당한다.

### 구현 원칙

- 참고 프로젝트 `3DRPG/Dialogue`의 데이터 분리와 글자별 출력 흐름은 재사용한다.
- 참고 프로젝트처럼 대화 재생기가 인벤토리나 플래그 시스템을 직접 변경하는 구조는 사용하지 않는다.
- 대화 중 게임 연출이 필요하면 타입이 구분된 신호를 전달하고 담당 Presenter 또는 Scene Handler가 처리한다.
- 문자열로 Hierarchy 오브젝트를 검색하지 않고 View가 전달받은 컴포넌트 참조로 표시한다.
- 튜토리얼 단계 저장과 대화 재생 상태를 분리해 재접속 시 중복 보상 / 중복 주문 / 중복 구매가 발생하지 않게 한다.

## INTRO

### 목적과 흐름

인트로는 플레이어가 왜 아기를 제작하게 되는지 세계관을 짧은 이미지 컷과 문장 연출로 전달한 뒤 Day 1 튜토리얼로 바로 연결한다.

1. 황새 장면에서 지옥의 아기 배송 거부와 초고령화 상황을 전달한다.
2. 기사 장면에서 아기 제작 사업이 등장한 배경과 핵심 문구를 강조한다.
3. SNS 광고 장면에서 플레이어 가게와 재료의 특징을 소개하고 본문 확대·이동과 마지막 강조를 사용한다.
4. Play 화면으로 전환한 뒤 플레이어 대화와 Day 1의 첫 행동 유도로 연결한다.

### 연출과 상태

* 컷별 배경 이미지 교체 / 문장 타이핑 또는 핵심 문장 강조 / 페이드와 짧은 슬라이드를 사용한다.
* 클릭 또는 터치로 현재 문장을 완성하거나 다음 컷으로 진행할 수 있게 하고, 인트로 전체 건너뛰기 입력을 제공한다.
* 황새 첫 말풍선은 자동 표시하지 않고 첫 입력에서 위로 올라오며 등장한다. 이후 인트로의 모든 문장은 글자별로 출력하고 출력 중 입력은 현재 문장만 완성한다.
* 클릭 진행 안내는 인트로가 끝날 때까지 점멸하며 기사 장면은 제목 강조와 본문 글자 출력, SNS 장면은 본문 기준 확대 / 화면 이동 / 마지막 화면 강조를 사용한다.
* 인트로 확인 여부를 저장해 같은 저장 슬롯에서 매번 반복하지 않게 하며, 인트로 종료 또는 건너뛰기 후 Day 1 튜토리얼 시작 상태가 같아야 한다.
* 인트로 중에는 마스코트 전체를 멈추고 숨기며 Day 1 핵심 튜토리얼 중에는 이동을 유지하고 팁 대사만 중지한다.
* Play 씬의 화면 View 루트는 비활성 상태로 시작하고 각 View의 `Show`가 자기 루트를 활성화한다. 상위 Canvas는 활성 상태를 유지해 초기화 중 불필요한 패널 연출과 효과음이 재생되지 않게 한다.
* 공용 `PanelTweenView` / `UIHighlightView`를 이미지 등장, 캐릭터 대화, 행동 유도 화살표, 입력 차단에 재사용한다.

## MVP_RESPONSIBILITY

* Day 1은 지정 행동 외 입력을 제한하는 Blocking Guide로 핵심 플레이 루프를 1회 완주시킨다.
* Day 2 이후는 실제 상황이 발생했을 때 Focus Guide 또는 Context Guide를 한 번 표시한다.
* 저장 상태에는 튜토리얼 단계와 개별 가이드 표시 여부만 추가하고 주문 / 구매 / 인벤토리 / 제작 / 배송 / 결산 완료 여부는 기존 Model 상태를 조회한다.
* 재접속 시 저장된 단계와 실제 게임 상태를 함께 확인하고 이미 끝난 행동은 자동으로 건너뛴다.
* 튜토리얼은 기존 시스템의 구매 / 제작 / 배송 / 결산 규칙을 중복 구현하지 않는다.
* 대화 시스템은 대사와 연출 신호만 전달하고 실제 행동 성공 여부와 단계 완료는 담당 프레젠터가 기존 Model 결과를 확인해 판정한다.
* 풀링 주문 / 상품 / 아이템 슬롯은 ID로 현재 활성 슬롯을 조회해 `TutorialView`에 런타임 연결하고 풀 반환이나 화면 갱신 이후 이전 참조를 유지하지 않는다.
* 행동 대상은 처음 한 번만 크기를 강조하고 이후에는 원래 상태를 유지하며 화살표만 위치 이동과 깜빡임을 반복한다.

* 공용 대화는 Player 이름 프레임 숨김 / 상대 NPC 유지 / 비화자 초상화 명암 / 원본 비율 유지 / 대화 중 마스코트 팁 억제와 숨김·복귀 연출을 연결했다.

## IMPLEMENTED_FLOW

* 공용 대화 시스템은 데이터 / View / Presenter를 분리하고 글자별 출력 / 문장 완성 / 다음 줄 / 건너뛰기 / 종료 / 연출 신호를 제공한다. 대화는 다른 Model을 직접 변경하지 않는다.
* `TutorialModel / TutorialSaveData`는 인트로 완료 / Day 1 현재 단계 / 개별 후속 가이드 완료 상태를 저장하고, 실제 주문·구매·인벤토리·제작·배송·결산 상태와 함께 다음 단계를 결정한다.
* Day 1은 전용 Easy 주문 1건과 제작 할당량 1건을 사용하며 주문 확인·수락 -> 상점 구매 -> 인벤토리 확인 -> 제작·평가 -> 직접 배송 -> 일일 결산 순서로 진행한다.
* Day 1 동안 현재 단계 외 입력을 제한하고 공용 강조와 동적 슬롯 ID 재탐색을 사용한다. 완료 후 일반 주문 생성과 일반 입력 상태로 복귀한다.
* 후속 가이드는 최초 복수 주요 요구 / 실제 파츠 품절과 빠른 재입고 / Day 4 정비 / Day 5 연구와 잠금 파츠 / 누적 영업일 2일차 업적 / Day 7 직원 / 첫 주간 결산과 가계부를 조건별 1회 표시한다.
* Day 7 직원 인트로 전에 일반 패널을 닫고 듀라한 대화를 재생하며, 대화 후 고용 탭과 듀라한 슬롯을 안내한다. 슬롯 활성 상태와 연출 알파가 분리되어 가이드 종료 후 정상 표시된다.
* 저장·재접속 시 이미 완료한 행동과 가이드를 반복하지 않으며 중복 주문 / 구매 강제 / 보상을 발생시키지 않는다.
* 화면의 스킵 버튼과 에디터 Space 입력은 현재 표시 중인 튜토리얼·가이드만 완료 처리하고 실제 게임 상태는 변경하지 않는다.
