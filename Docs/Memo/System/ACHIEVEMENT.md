# ACHIEVEMENT

## PURPOSE

업적 분류 / 판정 원본 / 단계 / 보상 / 표시 범위의 기획과 미결정 사항을 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 영업일과 가계부는 [DAY.md](DAY.md) / 주문 상태는 [ORDER.md](ORDER.md) / 제작 결과는 [CRAFT.md](CRAFT.md) / 직원 상태는 [UPGRADE.md](UPGRADE.md)를 따른다.

업적 시스템 내부 목차

* 업적 분류와 형태
* 판정 시점과 데이터 원본

## CONFIRMED

### 분류와 형태

* 업적 분류는 `영업 / 주문 / 제작 / 기타`를 사용한다.
* 고용 / 직원 수 / 주급 / 직원 배송처럼 가게 운영과 직접 연결되는 직원 업적은 `영업`에 포함하고 별도 고용 분류를 추가하지 않는다.
* 단일형 업적은 한 번 조건을 달성하면 영구 완료된다.
* 단계형 업적은 하나의 슬롯과 업적 ID를 계속 사용하며 현재 단계 완료 후 같은 슬롯을 다음 단계 목표로 갱신한다.
* 한 번의 판정에서 여러 단계 목표를 넘으면 달성한 모든 단계를 순서대로 확정하고 각 단계 보상을 모두 지급한다.
* 최종 단계 완료 후에는 영구 완료 상태가 된다.

### 진행도 / 숨김 / 알림

* 진행형 업적은 숫자 진행도와 진행 게이지를 함께 표시한다.
* 숨김 업적도 슬롯은 항상 표시하며 달성 전 이름과 조건은 `?`로 가린다.
* 숨김 업적의 현재 숫자 진행도 / 진행 게이지 / 보상 정보는 달성 전에도 표시한다.
* 숨김 업적 달성 후 실제 이름과 설명을 공개한다.
* 새 단계 또는 단일형 업적을 달성하면 메인 화면의 업적 버튼에 알림 아이콘을 표시한다.
* 즉시 팝업과 강제 업적 화면 전환은 MVP에 포함하지 않는다.
* 업적 버튼은 기본 상태를 유지하고 신규 알림 아이콘만 깜빡인다. 버튼 클릭 시에는 다른 사이드 액션 버튼과 같은 짧은 눌림·복귀 연출을 사용한다.

### 판정 시점과 원본

* 업적 판정은 영업 종료 후 결산 데이터 최종 확정 전에 한 번 수행한다.
* 날짜 / 일일 기록 / 주간 집계 / 주문 결과 / 제작 결과 / 배송 평가 / 직원 상태의 기존 확정 원본을 읽고 같은 통계를 업적 시스템이 중복 소유하지 않는다.
* 현재 기록에 보존되지 않아 과거 집계가 불가능한 정보만 담당 `DailyRecord` 하위 기록에 확정 결과로 추가한다.
* 업적 보상으로 같은 결산의 진행도가 추가로 증가해도 해당 영업 종료 안에서 재귀 판정하지 않고 다음 결산에서 반영한다.

### 보상과 수동 수령

* 보상은 골드 / 파츠 해금 / 상품 해금 / 정비 해금 / 장식 해금 / 무보상을 지원한다.
* 업적은 결산 직전 판정으로 달성 상태만 확정하고 보상은 업적 화면의 `보상 획득` 버튼으로 나중에 수령한다.
* 업적 슬롯의 수령 버튼은 별도 상태 Text를 표시하지 않는다. 수령 가능 여부는 버튼 활성 상태로 구분하고 완료 / 미달성 / 진행 상태는 기존 업적 정보와 진행도 표시를 사용한다.
* 미수령 보상이 있어도 결산 확인 / 다음 영업일 진행 / 다른 게임 기능을 막지 않는다.
* 전체와 분류별 업적 목록은 미수령 보상이 있는 업적을 최상단에 우선 배치하고, 미수령 그룹과 나머지 그룹 내부에서는 기존 데이터 순서를 유지한다.
* 골드 보상은 수령 시점의 자금에 반영하고 수령한 영업일의 기타 수입으로 기록한다. 달성한 과거 결산을 소급 변경하지 않는다.
* 업적 골드 보상은 고정 금액이며 주문 난이도 / VIP / 직원 / 기타 배율의 영향을 받지 않는다.
* 파츠 / 상품 해금은 기존 `PlayStateModel`의 상품 해금 상태를 사용한다.
* 정비 해금은 정비 단계를 지급하지 않고 대상 정비의 최초 상품을 구매 가능한 상태로 해금하며 일반 가격 / 구매 / 업그레이드 규칙은 유지한다.
* 장식 시스템 구현 전에는 장식 보상 ID만 해금 상태에 예약하고 이후 실제 장식 시스템이 같은 ID를 사용한다.
* 한 번의 수령에서 지급할 보상을 먼저 검증하고 지급 실패 시 적용한 보상과 수령 상태를 함께 원상 복구해 중복 지급을 막는다.
* 한 번의 판정에서 여러 단계를 달성하면 달성 단계는 모두 확정하되 같은 슬롯에서 미수령 단계 보상을 순서대로 수령한다.

## DATA

### AchievementData

* 업적 ID / 분류 / 이름 / 설명 / 숨김 여부 / 진행도 판정 타입 / 단계 목록을 가진다.
* 단일형은 단계가 하나인 업적으로 표현해 별도 판정 구조를 만들지 않는다.

### AchievementStageData

* 단계 목표값 / 단계 표시 이름과 설명 / 보상 목록을 가진다.

### AchievementRewardData

* 보상 타입 / 골드 값 또는 대상 ID를 가진다.
* 무보상은 빈 보상 목록 또는 명시적 무보상 타입으로 표시한다.

### AchievementState

* 달성 단계 / 보상 수령 완료 단계 / 최종 완료 여부 / 신규 달성 알림 여부를 보관한다.
* 달성 단계와 수령 완료 단계를 분리해 결산 후 나중에 보상을 받아도 달성 기록과 미수령 보상이 유지되게 한다.
* 메인 업적 버튼 알림은 새 달성 또는 미수령 보상이 있으면 표시하며 화면을 열어도 미수령 보상이 남아 있으면 유지한다.

### 판정 원본 보완

* `DailyCraftRecord`: 활성 테마 여부 / 완성 테마 여부 / 상극 개수 / 목표 테마 달성 여부 / 모든 주요 요구와 희망 달성 여부를 보존한다.
* `DailyOrderRecord`: 배송 방식 / 배송 직원 ID / 마감일 당일 정상 납품 여부를 보존한다.
* `DailyRecord`: 당일 직원 고용 성공 횟수를 보존한다.
* S등급 / 납품 / 주요 요구 / 희망 / 순이익은 기존 일일 및 주간 기록을 집계한다.
* 기존 `PlayStateModel.HighGradeEvaluationCount`는 S, A, B등급 합계이므로 S등급 또는 A등급 이상 업적의 단일 원본으로 사용하지 않는다.

업적 작업 시작과 종료 시 전체 확인하고 변경 사항을 즉시 반영한다.
