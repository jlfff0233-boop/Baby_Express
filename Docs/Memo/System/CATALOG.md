# CATALOG

## PURPOSE

파츠 카탈로그 / 정보 조회 / 검색과 필터 / 통계 항목의 기획과 미결정 사항을 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 상품 원본은 [SHOP.md](SHOP.md) / 보유량은 [INVENTORY.md](INVENTORY.md) / 테마 정보는 [CRAFT.md](CRAFT.md) / 해금 상태는 [UPGRADE.md](UPGRADE.md)를 따른다.

## CONFIRMED

확정 규칙

### 목적과 책임

* 카탈로그는 파츠 정보를 확인하는 읽기 전용 참고 화면이며 해금된 파츠 상세에서 같은 상품의 상점 상세로 이동할 수 있다.
* 카탈로그는 메인 화면의 서브 버튼으로 진입한다.
* `PurchasableDataMap` / `PartsData` / `InventoryModel` / `PlayStateModel`의 기존 데이터와 해금 상태를 재사용한다.
* 카탈로그는 구매 / 장착 / 제작 / 점수 계산 / 해금을 처리하지 않고 기존 시스템의 데이터를 읽어 표시만 한다.

### 목록과 상세

* 해금 여부와 관계없이 `PurchasableDataMap`에 등록된 모든 파츠를 목록에 표시하고 파츠가 아닌 상품은 제외한다.
* 슬롯은 아이콘 / 이름 / 파츠 타입 / 잠금 표시만 사용하며 제작 코스트 / 테마 / 보유량은 상세에서만 표시한다.
* 해금된 파츠 상세는 아이콘 / 이름 / 설명 / 파츠 타입 / 제작 코스트 / 복수 테마 / 상극 정보 / 현재 보유 수량을 표시한다.
* 상세 정보는 설명 / 파츠 타입 / 제작 코스트 / 테마 / 상극 테마 / 해금 상태 / 보유 수량을 각각 독립된 UI 항목으로 표시한다.
* 상세 UI에서 기존 고정 라벨이 있는 해금 상태 / 보유 수량은 값 Text에 실제 값만 전달하고, 별도 고정 라벨이 없는 설명 / 파츠 타입 / 제작 코스트 / 테마 / 상극 테마는 값 Text에 항목명을 함께 표시한다.
* 잠긴 파츠는 슬롯 아이콘을 검은색 실루엣으로 표시하고 이름은 `???`로 가리며 파츠 타입과 잠금 상태만 공개한다.
* 잠긴 파츠의 설명 / 테마 / 제작 코스트 / 보유량은 공개하지 않고 잠금 안내만 표시한다.

### 검색 / 필터 / 정렬

* 검색은 해금되어 이름이 공개된 파츠만 실제 이름으로 검색하며 대소문자와 앞뒤 공백을 무시한다.
* 파츠 / 테마 Button으로 분류 기준을 선택하고 공용 분류 Dropdown은 선택한 버튼에 맞춰 파츠 타입 또는 테마 항목으로 교체한다.
* 해금 여부와 보유 여부는 독립 필터로 제외하고 정렬 Dropdown의 해금 우선 / 보유 우선 항목으로 제공한다. 제작 코스트 기준은 필터와 정렬 모두 사용하지 않는다.
* 테마 분류 Dropdown은 성질 테마와 종족 테마를 같은 목록에 표시하며 옵션 순서와 실제 enum 값의 대응은 코드에서 생성한다.
* 테마처럼 잠긴 상세 정보가 필요한 검색과 필터에는 잠긴 파츠를 결과로 노출하지 않아 실제 정보를 역으로 추측할 수 없게 한다.
* 현재 UI에 존재하는 정렬 기능은 유지하고 검색 / 필터 / 정렬 결과 구성은 무상태 Builder에서 처리한다.

### 확장 범위

* 인기도 / 판매 또는 사용 통계는 실제 게임 규칙과 연결될 때만 추가하고 장식용 수치로 만들지 않는다.
* 파츠 희귀도는 해금 시점 / 연구 조건 / 가격 / 재고 / 제작 코스트와 역할이 겹치므로 데이터와 UI에 추가하지 않는다.
* 고급 통계와 카탈로그에서 제작 화면으로 이동하는 기능은 MVP 이후로 둔다.

## IMPLEMENTATION_STATUS

* 카탈로그 1차 구현을 완료했다: 전체 파츠 목록 / 검색 / 필터 / 정렬 / 페이지 구조 / 잠긴 파츠 실루엣과 잠금 아이콘 / 정보 은닉 / 상세 / 상점 이동 / 슬롯 재사용.
* 공용 분류 Dropdown은 파츠 / 테마 Button 선택에 따라 옵션을 교체하고 성질 / 종족 테마 문구와 실제 enum 값을 코드에서 같은 순서로 생성한다. Inspector에는 파츠 / 테마 Button과 공용 Dropdown을 연결한다.
* 현재 파츠 수가 한 페이지 용량 이하이므로 여러 페이지 이동과 마지막 페이지 표시는 후속 검증 대상으로 유지한다.
* 신규 파츠 해금 시 카탈로그 알림 상태를 저장하고 카탈로그 화면 확인 후 해제한다. 새 게임의 초기 해금 파츠는 신규 알림으로 처리하지 않는다.

## IMPLEMENTATION_PLAN

1. `CatalogPresenter`가 `PurchasableDataMap` / `InventoryModel` / `PlayStateModel`을 전달받아 화면 진입 시 최신 해금 상태와 보유량을 조회한다.
2. 무상태 `CatalogListBuilder`가 파츠 추출 / 공개된 이름 검색 / 파츠 타입 또는 테마 필터 / 이름, 아이디, 해금, 보유 정렬을 수행하고 원본 상태는 변경하지 않는다.
3. `CatalogViewDataBuilder`가 해금된 파츠의 슬롯과 상세 데이터, 잠긴 파츠의 실루엣 / `???` / 잠금 안내 데이터를 생성한다.
4. `CatalogPresenter`는 검색어 / 필터 / 정렬 상태와 현재 선택 파츠를 소유하고 슬롯 선택 / 상세 표시 / 상세 닫기 / 해금 파츠의 상점 이동 요청을 중재한다.
5. `CatalogView`는 검색 / 필터 / 정렬 / 슬롯 선택 / 상세 닫기 / 화면 닫기 이벤트만 전달하고 Model을 직접 참조하지 않는다.
6. 전체 목록 / 잠긴 정보 은닉 / 검색 / 복합 필터 / 검색 결과 없음 / 해금 및 보유량 변경 후 재진입 / 다른 Model 상태 불변을 검증한다.

## PENDING

미구현 / 미결정

* 한 페이지 용량을 초과하는 파츠 데이터로 이전 / 다음 페이지와 마지막 페이지 슬롯 표시 검증.
* 현재 `CatalogView` 내부의 생성 슬롯 숨김 / 재사용 구조를 별도 오브젝트 풀로 전환할지 후속 최적화 시 결정.
* 판매 통계를 상점 구매량 / 인벤토리 판매량 / 제작 사용량 / 최근 주문 수요 중 무엇으로 정의할지 확정.
* 인기도가 주문 생성이나 수요에 영향을 주는지 확정하고 연동이 없으면 제외.
* 카탈로그 정보 해금과 정비의 연결 단계 확정.
* 테마 하나를 완성할 때마다 지급할 보상의 완성 판정 기준 / 보상 종류와 수치 / 수령 방식 / 중복 지급 차단 상태 확정과 연결.
