# INVENTORY

## PURPOSE

인벤토리 적재 / 스택 / 슬롯 / 판매 / 삭제 / 화면 흐름의 기획과 미결정 사항을 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 구매 성공 시 인벤토리 추가 흐름은 [SHOP.md](SHOP.md) / 제작 파츠 소비는 [CRAFT.md](CRAFT.md)를 따른다.

* 미구현 / 미결정

## CONFIRMED

확정 규칙

* InventoryModel은 일반 C# Model이며 상품 ID별 전체 보유 수량을 관리한다.
* InventoryModel은 아이템 수량 / 슬롯 용량 / 스택 용량 / 아이템 증감 규칙을 담당하고 목록 표시용 필터와 정렬은 직접 처리하지 않는다.
* InventoryListBuilder는 상태를 보관하지 않고 InventoryModel의 아이템 목록을 필터·정렬해 99개 단위 InventoryStack 목록으로 변환한다.
* InventoryListBuilder는 InventoryModel.MaxStackQuantity를 사용해 스택 최대 수량을 중복 선언하지 않는다.
* 기본 용량은 50슬롯 / 한 슬롯 최대 수량은 상품 종류와 관계없이 99개이다.
* 같은 상품이 99개를 초과하면 복수 스택으로 나누고 기존 부분 스택을 먼저 채운다.
* 사용 슬롯 수는 모든 상품의 스택 수 합계이며 시설처럼 인벤토리 용량을 사용하지 않는 상품은 별도 규칙으로 제외한다.
* 여러 상품을 한 번에 추가할 때 최종 슬롯 수를 사전 검증하고 용량을 초과하면 전체 추가를 실패 처리한다.
* 복수 스택을 구분하는 슬롯 ID와 원본 상품 ID를 분리한다.
* 인벤토리 용량은 사용 슬롯 수 / 최대 슬롯 수로 표시한다.
* 인벤토리 상세 패널은 상품의 전체 보유 수량이 아니라 현재 선택한 스택 수량을 표시한다.
* ItemSlotView와 슬롯 프리팹은 인벤토리와 제작 화면에서 공용으로 사용하되 각 View와 Presenter는 분리한다.
* ItemSlotView는 아이콘 / 이름 / 현재 스택 수량 / 선택 입력만 담당하고 Model을 직접 참조하지 않는다.
* InventoryDetailView는 공용 사이드 패널 하나를 사용하고 아이콘 / 이름 / 설명 / 선택 스택 수량을 표시한다.
* 상점 이동 / 사용 / 제작 이동 입력은 InventoryPresenter를 거쳐 상위 중재자에게 전달한다.
* InventoryPresenter는 ShopView 또는 CraftView를 직접 갱신하지 않는다.
* 판매와 삭제는 MIN / MAX / 증감 / 직접 입력을 지원하고 잘못된 문자열 / 음수 / 보유량 초과를 거부한다.
* 기본 판매가는 상품 `BasePrice`의 50%이며 상점 할인과 가격 변동이 반영된 `CurrentPrice`는 사용하지 않는다.
* 고블린 재고 담당을 고용한 동안 판매율은 50%에 15%p를 더한 65%이며 50%에 1.15배를 곱하지 않는다.
* 판매 가능한 상품은 BabyPart / Consumable이며 Furniture / Equipment / Expansion은 인벤토리 재판매 대상에서 제외한다.
* 직원 활성 효과는 `EmployeeModel`에서 조회하고 실제 판매 수익 계산과 인벤토리 감소 / 자금 증가는 기존 판매 처리에서 한 번만 적용한다.
* 목록은 기본 / 이름 / 가격 / 수량을 기준으로 오름차순과 내림차순 정렬할 수 있다.
* 전체 / 파츠 / 시설 / 소모품은 메인 카테고리 Button / 세부 분류와 정렬은 공용 TMP_Dropdown을 사용한다.
* 메인 카테고리 버튼을 누르면 공용 분류 옵션을 교체하고 0번 전체 항목으로 초기화해 목록을 즉시 갱신하며 같은 버튼을 다시 눌러도 해당 카테고리 전체로 돌아간다.
* 전체와 소모품은 현재 세부 분류가 하나뿐이므로 공용 분류를 표시하되 입력을 비활성화하고, 카테고리 변경 시 정렬을 유지한다.
* 인벤토리 재진입 시 현재 카테고리 / 분류 / 정렬을 유지한다.
* 인벤토리 내부의 보유 대상은 아이템 / 상점에서 판매 중인 대상은 상품으로 표현한다.
* 인벤토리 목록 슬롯은 `GameManager`가 소유한 공용 `PoolManager`와 Unity `ObjectPool`을 사용하고 `ItemSlotView` 프리팹을 풀 구분 기준으로 삼는다.
* 목록 갱신 시 현재 활성 슬롯을 풀로 반환한 뒤 필요한 수만 다시 대여하며 같은 인스턴스의 등장 연출은 최초 한 번만 실행한다.
* 슬롯 반환 전 선택 이벤트 / 슬롯 ID / 아이템 ID / 선택 상태 / 툴팁 / Tween / 크기 / 투명도를 초기화하고 재사용 시 ViewData와 형제 순서를 다시 설정한다.

## FLOW

입력 -> 처리 -> 결과

* 구매 적재: PurchaseModel 사전 검증 -> InventoryModel 수용 가능 여부 -> 전체 구매 성공 시 아이템 추가.
* 목록 표시: InventoryPresenter 조회 -> 정렬 / 필터 결과를 ViewData로 변환 -> InventoryView와 ItemSlotView 갱신.
* 상세 표시: 슬롯 선택 -> InventoryPresenter -> 선택 스택 조회 -> 공용 상세 패널 갱신.
* 판매 / 삭제: View 입력 -> Presenter -> InventoryModel 검증과 변경 -> 목록 / 상세 / 자금 표시 갱신.
* 화면 이동: 상세 패널 요청 -> InventoryPresenter -> PlayScene 또는 추후 RuntimePresenter -> 대상 화면 전환.

## PENDING

미구현 / 미결정

* BasePrice 50% 기본 판매가 / 고블린 고용 중 65% 판매율 / 상품군별 판매 가능 여부를 기존 판매 처리에 연결한다.
* 빈 인벤토리 슬롯 50개를 모두 표시할지 보유 아이템 슬롯만 표시할지 확정.
* 인벤토리 슬롯 확장 1회 증가량과 최대 확장 한도 확정.
* 삭제 가능 상품과 Consumable 사용 흐름은 실제 소모품 연결 단계에서 확정.
* 사용 / 제작 / 상점 이동 요청은 대상 화면 흐름이 정리된 뒤 PlayScene 또는 RuntimePresenter에서 연결.
* 판매 / 삭제 경계값과 실패 시 수량 / 자금 원상 유지 재검증.
