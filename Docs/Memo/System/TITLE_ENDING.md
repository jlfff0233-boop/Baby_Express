# TITLE / ENDING

## PURPOSE

타이틀 진입 기능 / 게임 종료 후 총 결산 / 재시작과 타이틀 복귀 범위를 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 이어하기 / 이번 주부터 다시 시작 / 처음부터 다시 시작에 필요한 저장과 복구 규칙은 [SAVE_LOAD.md](SAVE_LOAD.md)를 따른다.
* 엔딩 총 결산의 원본 기록은 [DAY.md](DAY.md)의 일일 / 주간 기록과 가계부 데이터를 재사용한다.

## CONFIRMED

### 타이틀 1차

* 타이틀은 `새 게임 / 이어하기 / 설정 / 종료` 네 기능을 제공한다.
* 새 게임은 5개 저장 슬롯 중 빈 슬롯을 선택하거나 기존 슬롯의 덮어쓰기를 확인한 뒤 기존 실행 상태를 재사용하지 않고 새로운 플레이 상태를 초기화해 Play 씬으로 진입한다.
* 이어하기는 공용 슬롯 화면에서 유효한 저장 슬롯을 선택하고 저장된 플레이 상태를 복구한 뒤 Play 씬으로 진입한다. 빈 슬롯과 손상 슬롯은 불러올 수 없다.
* 설정은 Play와 같은 공용 설정값과 `SettingsView` 구조를 사용한다.
* 종료는 실행 중인 게임을 종료하며 저장 여부를 임의로 변경하지 않는다.
* 타이틀 메인 화면은 기본 배경을 고정하고 별도 사선 장식 배경만 천천히 이동시킨다. 로고는 최초 등장 후 작은 폭으로 반복 이동하고 새 게임 / 이어하기 / 설정 / 종료 버튼은 최초 진입에만 순서대로 등장한 뒤 고정한다.

### 엔딩 1차

* 엔딩 화면은 해당 플레이의 총 결산을 읽기 전용으로 표시한다.
* 총 결산은 기존 일일 / 주간 결산과 가계부 기록을 원본으로 사용하고 엔딩 전용으로 같은 거래나 주문 결과를 중복 집계하지 않는다.
* 일반 엔딩 화면은 `이어서 하기 / 아예 처음부터 다시 시작 / 시작 화면으로` 세 기능을 제공한다. `이번 주부터 다시 시작`은 파산 화면에서만 제공한다.
* 이어서 하기는 엔딩 화면을 닫고 다음 영업일 진행을 계속한다.
* 아예 처음부터 다시 시작은 기존 런타임 플레이 상태를 폐기하고 새 게임과 같은 초기 상태로 Play 씬을 시작한다.
* 시작 화면으로는 타이틀 씬으로 이동하며 새 게임이나 저장 데이터 삭제를 자동 실행하지 않는다.
* 엔딩 총 결산은 같은 성격의 누적 기록을 운영 / 경제 / 주문 평가 / 제작 / 업적 단위 슬롯으로 묶어 줄바꿈 표시하고 누적 수입은 초록색 / 누적 지출은 빨간색으로 구분한다.
* 엔딩 메달은 최종 실적에 따라 금 / 은 / 동으로 확장하되 세부 기준 확정 전에는 금메달을 기본 표시한다.

### 저장 / 불러오기 의존성

* 이어하기는 기본 저장 / 불러오기 구현 이후 연결한다.
* 이번 주부터 다시 시작은 주간 시작 스냅샷의 생성 / 보관 / 복구가 구현되어야 사용할 수 있다.
* 처음부터 다시 시작은 모든 런타임 Model을 새 게임 기준으로 다시 생성하는 단일 초기화 흐름을 재사용한다.
* 타이틀과 엔딩 View가 저장 데이터 구조를 직접 읽거나 런타임 Model을 직접 초기화하지 않고 담당 중재자를 통해 요청한다.

## MVP_RESPONSIBILITY

* 타이틀 중재자는 새 게임 / 이어하기 / 설정 / 종료 입력을 전달하고 저장 상태에 따라 이어하기 가능 여부를 갱신한다.
* 엔딩 중재자는 총 결산 표시 데이터를 구성하고 이번 주 복구 / 새 게임 / 타이틀 이동 요청을 중재한다.
* 총 결산 Builder는 기존 확정 기록을 읽어 표시용 데이터만 생성하며 자금 / 주문 / 업적 / 해금 상태를 변경하지 않는다.
* 저장 시스템은 이어하기 데이터와 주간 시작 스냅샷의 실제 생성 / 검증 / 복구를 담당한다.

## IMPLEMENTATION_STATUS

* 타이틀의 새 게임 / 이어하기 / 설정 / 종료와 공용 5개 슬롯 View를 연결했다. 저장 슬롯이 하나도 없으면 새 게임은 1번 슬롯으로 즉시 시작하고, 사용 중인 슬롯이 있으면 빈 슬롯 선택 또는 기존 슬롯 덮어쓰기 확인 후 시작한다.
* 타이틀은 `PlayStartRequest`로 새 게임 또는 불러오기 방식과 슬롯 번호만 전달하고 Play 씬의 `PlaySceneStartHandler`가 초기 저장 또는 런타임 복구를 실행한다.
* 엔딩은 전체 업적의 최종 단계 달성을 현재 조건으로 사용하고 결산 처리 이후 표시한다. 완료된 일일 기록과 기존 결산 계산을 재사용해 총 운영 기간 / 최종 골드 / 누적 수입·지출·순이익 / 완료 주문과 등급 / 제작과 사용 파츠 / 직원 배송 / 직원 수 / 업적 수를 표시한다.
* 엔딩의 이어서 하기 / 처음부터 다시 시작 경고와 확인 / 시작 화면 복귀를 연결했다.
* 타이틀 새 게임·이어하기부터 Play 저장·복구 / 파산 주간 복구 / 엔딩 이어서 하기·처음부터 다시 시작·타이틀 복귀까지 전체 흐름을 사용자 Play Mode에서 확인했다.
* 타이틀 로고 등장과 반복 이동 / 메뉴 버튼 순차 등장 코드를 연결하고 전체 패널 확대 대신 타이틀 요소별 연출을 사용한다.
* 엔딩의 기존 단일 누적 Text를 항목별 `EndingSlotView`와 표시 데이터로 교체하고 누적 수입·지출 색상과 금메달 기본 표시를 연결했다.

## IMPLEMENTATION_PLAN

1. [완료] 저장 / 불러오기에서 5개 슬롯 조회 / 새 게임 초기화 / 이어하기 복구 / 수동·자동 저장 / 주간 시작 스냅샷 복구 진입점을 제공한다.
2. [완료] 공용 슬롯 View를 `NewGame / Load / Save` 모드로 연결하고 타이틀의 새 게임 / 이어하기와 Play 설정의 저장 탭에서 재사용한다.
3. [완료] 타이틀의 설정 Presenter 참조와 패널 초기 상태를 연결하고 네 버튼을 새 게임 초기화 / 이어하기 복구 / 공용 설정 / 종료 흐름에 연결한다.
4. [완료] 엔딩 총 결산 항목과 현재 엔딩 조건을 확정하고 기존 기록을 사용하는 표시 데이터 Builder를 구현한다.
5. [완료] 엔딩 View와 중재자를 구현해 총 결산 표시 / 이어서 하기 / 새 게임 / 타이틀 이동을 연결한다.
6. [완료] 빈·정상·손상 슬롯 / 덮어쓰기 / 자동·수동 저장 / 정상 이어하기 / 주간 복구 / 완전 초기화 / 타이틀 복귀 / 엔딩 재진입을 검증한다.

## PENDING

* 업적 데이터가 충분히 추가되면 전체 업적 완료 대신 엔딩 대상으로 지정한 특정 업적들의 완료 여부를 판정하도록 확장.
* 엔딩 금 / 은 / 동 메달의 실적 기준을 데이터와 함께 확정하고 기본 금메달 표시를 실제 판정으로 교체.
* 타이틀 로고 / 버튼 / 사선 장식 배경 연출의 최종 이동 폭과 속도 및 화면 비율별 경계 확인.

타이틀 / 엔딩 범위나 저장 의존성이 변경될 때 갱신하고 실제 구현과 검증 완료 상태는 [DONE.md](../DONE.md)에 반영한다.
