## CONFIRMED

확정 규칙

### 영업일

* 새 게임의 Day 1 초기 보유 자금은 500G이며 초기 무료 파츠는 지급하지 않는다.
* 하루는 제작 완료 수가 일일 제작 할당량에 도달하거나 더 이상 처리할 수 있는 수락 대기 주문과 제작 진행 주문이 없을 때 자동으로 끝난다.
* 일일 제작 할당량을 채우면 자동으로 영업 종료 처리와 결산을 시작하되 다음 날짜 증가는 결산 확인 후에만 실행한다.
* 수락 대기 주문과 제작할 진행 주문이 모두 없으면 할당량 미달이어도 자동으로 영업 종료 처리와 결산을 시작한다.
* 자동 종료는 오늘 생성되거나 받은 주문을 모두 처리했다는 의미가 아니며 아직 받지 않은 주문 / 진행 중 주문 / 배송 대기와 배송 중 주문은 유지한다.
* 주문 기한 / 재입고 / 주간 평가는 날짜 단위로 처리하고 TopBar 영업 시각은 실시간 경과가 아니라 당일 제작 진행률을 시각화하는 값으로 사용한다.
* 영업 종료 확정 전에는 날짜 / 재입고 / 신규 주문 상태를 변경하지 않는다.
* 영업 종료 -> 오늘 도착 배송 처리 -> 주문 기한 판정 -> 직원 고용 일수 기록 -> 7일째 주급 지급 -> 당일 기록 확정 -> 일일 결산 -> 필요 시 주간 결산 -> 다음 날 확인 -> 날짜 증가 -> 재입고 -> 신규 주문 생성 순서이다.
* 결산 표시 중에는 날짜 증가 / 재입고 / 신규 주문 생성을 실행하지 않는다.

### 일일 제작 할당량

* 일일 할당량은 그날 제작 완료할 수 있는 주문 수이며 제작 완료가 확정될 때 한 건을 처리한 것으로 집계한다.
* 수락 / 거절 / 상점 구매 / 인벤토리 확인 / 배송 출발과 도착은 일일 제작 할당량을 직접 증감시키지 않는다.
* 제작 완료 후 주문을 취소해도 취소 행동이 할당량을 추가 소모하지 않고 이미 집계된 제작 완료 수를 되돌리지 않는다.
* 취소한 제작물은 배송하지 않아 수익을 얻지 못하고 파츠와 제작물도 복구하지 않으므로 별도의 할당량 페널티는 추가하지 않는다.
* 배송하지 않은 제작 완료 주문이 남아 있어도 일일 제작 할당량을 채우면 자동으로 결산을 표시하고 해당 주문은 다음 날 배송 대기로 이월한다.
* 일일 제작 할당량은 다음 날 초기화하고 사용하지 않은 양은 이월하지 않는다.
* 일일 제작 할당량은 매일 무작위로 정하지 않고 기본값과 제작 설비 정비 단계에 따라 정하며 일반적인 신규 주문 수보다 낮게 유지한다.
* 기본 일일 제작 할당량은 2건이며 튜토리얼 첫날만 1건으로 적용하는 방향으로 연결한다.
* 가고일 운반원을 고용하면 현재 시설 정비가 결정한 일일 제작 할당량에 +1을 적용하고, 저장 복구 시 같은 직원 보너스를 중복 합산하지 않는다.
* 제작 설비의 할당량 증가는 구매 당일이 아니라 다음 영업일부터 적용해 진행률 분모와 자동 결산 조건이 영업 중 바뀌지 않게 한다.
* TopBar 진행률은 오늘 제작 완료 수 / 현재 일일 제작 할당량을 표시한다.
* 할당량을 채운 마지막 제작의 완료 패널은 그대로 표시하고 확인 또는 배송 처리가 끝난 직후 다른 행동을 잠근 뒤 결산으로 전환한다.

### 영업 시각 표시

* 영업 시작 시각은 `09:00` / 일일 제작 할당량 달성 시 마감 시각은 `21:00`으로 표시한다.
* 현재 시각은 `09:00 + 12시간 × (오늘 제작 완료 수 / 현재 일일 제작 할당량)`으로 계산하고 제작 완료 수가 바뀔 때만 갱신한다.
* 할당량이 2건이면 `09:00 -> 15:00 -> 21:00` / 3건이면 `09:00 -> 13:00 -> 17:00 -> 21:00` 순서로 표시한다.
* 수락 / 거절 / 구매 / 판매 / 배송 / 화면 체류 시간은 영업 시각을 변경하지 않으며 다음 영업일에는 제작 진행률과 함께 `09:00`으로 초기화한다.
* 시간의 단일 기준은 일일 제작 진행률이며 저장값 복구 후에도 현재 제작 완료 수와 할당량을 기준으로 다시 계산한다.

#### 할당량 예시

* 일일 제작 할당량이 2건이면 완료할 때마다 1 / 2 -> 2 / 2로 표시하고 중간 제작물을 취소해도 완료 수를 되돌리지 않으며 2 / 2에서 배송 대기 여부와 관계없이 영업 종료와 결산을 시작한다.

#### 1차 할당량 테스트값

* 기본 일일 제작 할당량은 2건으로 테스트하고 데이터에서 조정할 수 있게 한다.
* 처리할 주문이 없어 할당량 미달로 자동 종료되면 미사용 처리량 소멸 외 별도 페널티를 적용하지 않는다.

### 빠른 재입고

* 빠른 재입고는 상점에서 현재 선택한 상품 하나의 재고만 현재 최대 재고까지 즉시 충전한다.
* 빠른 재입고 이용료는 선택 상품 `BasePrice × 1.5`를 1차 테스트값으로 사용하며 상품의 실제 구매 비용은 이후 구매 시 `CurrentPrice × 구매 수량`으로 별도 지불한다.
* 재고가 이미 최대인 상품 / 잠긴 상품 / 잘못된 상품에는 빠른 재입고를 사용할 수 없다.
* 빠른 재입고는 하루 최대 3회 사용할 수 있고 남은 횟수는 이월하지 않으며 다음 영업일에 초기화한다.
* 빠른 재입고는 상점 재고 / 현재 자금 / 오늘 이용 횟수만 변경하고 인벤토리 수량은 직접 변경하지 않는다.
* 비용·횟수·상품 상태를 전부 사전 검증한 뒤 자금 차감 -> 선택 상품 재고 충전 -> 오늘 이용 횟수 증가 순서로 처리한다.
* 빠른 재입고 비용과 남은 횟수는 상점 상품 상세에서 표시하고 TopBar에는 별도로 표시하지 않는다.
* 빠른 재입고 이용료는 당일 기타 지출이 아니라 별도 항목으로 기록하고 일일·주간 경제 결산에 포함한다.

### 제작 불가와 파산

* 현재 인벤토리 / 상점 재고 / 당일 남은 빠른 재입고 횟수 / 현재 자금을 모두 고려해도 진행 주문 중 하나의 최소 구성을 마련할 수 없으면 파산으로 판정한다.
* 단순히 자금이 0 이하인지만 검사하지 않고 현재 자금으로 필요한 구매와 빠른 재입고 비용을 감당할 수 있는지 확인한다.
* 파산 계산은 먼저 몸통·눈·코·입 최소 조립 가능성을 검증하고 최대 제작 코스트 / 최대 파츠 수 / 제외 테마까지 반영한 뒤 실제 파산 이벤트에 연결한다.
* 주요 요구 / 희망 / 목표 테마는 제작 확정을 직접 차단하지 않으므로 파산 가능성 계산의 필수 조건으로 사용하지 않는다.
* 파산 화면에서는 완전히 다시 시작 / 현재 주의 시작 시점으로 돌아가기 중 하나를 선택한다.
* 현재 주의 시작 시점으로 돌아가기는 주간 시작 상태를 별도로 보관하는 저장 시스템과 연결한다.

### 달력

* TotalDay를 날짜 판정의 단일 원본으로 사용하고 월 / 일은 누적 영업일에서 계산한다.
* 1년은 364일 / 화면은 12개월이다.
* 1 / 4 / 7 / 10월은 31일이고 나머지 월은 30일이다.
* 현실보다 하루 적은 이유는 악마들이 개성을 추구해 하루를 제외했다는 설정이다.

### 기록과 결산

* 매 영업일 종료 후 일일 결산을 표시하고 7일마다 일일 기록을 집계한 주간 결산을 추가로 표시한다.
* 주간 결산 이후에도 기존 일일 / 주간 기록을 삭제하거나 초기화하지 않는다.
* 메인 화면의 서브 버튼 `가계부`에서 과거 주간 결산을 모아본다.
* 가계부는 과거 내역 조회용이며 영업 종료나 다음 날 전환을 실행하지 않는다.
* 결산 수치는 별도 결과 카운트를 중복 저장하지 않고 주문 결과와 당일 거래 기록을 집계한다.
* `DailyRecord`는 당일 성공 처리의 원본 내역을 보관하고 `DailySettlementData`는 결산 표시를 위해 원본 내역을 집계한 결과를 보관한다.
* `DailyRecordModel`은 현재 영업일 기록과 완료된 과거 일일 기록 목록을 보관하며 다음 날 시작 시 새 기록을 생성하되 완료 기록을 삭제하지 않는다.
* `SettlementModel`은 확정된 `DailyRecord`를 운영 / 주문 / 평가 / 경제 / 구매 / 소비 파츠 / 빠른 재입고 결산 데이터로 변환한다.
* 당일 기록은 주문 결과 / 상점 구매 / 인벤토리 판매 / 제작 파츠 소비 / 정비 지출 / 직접 배송비 / 직원 고용비 / 직원 주급 / 기타 수입과 지출을 구분한다.
* 일일 결산은 정상 납품 / 지연 납품 / 거절 / 자동 거절 / 취소 / 최종 실패 수와 주요 요구 충족 결과를 표시한다.
* 제작과 배송 시점이 달라질 수 있으므로 오늘 제작 완료 / 오늘 취소·폐기 / 오늘 배송 출발 / 오늘 도착·납품 / 현재 배송 대기 / 현재 배송 중 수를 구분한다.
* 일일 결산에는 오늘 사용한 제작 할당량 / 최대 할당량도 표시한다.
* 경제 결산은 소비 파츠 / 상점 구매 목록과 지출 / 정비 지출 / 직접 배송비 / 직원 고용비 / 지급일의 직원 주급 / 주문 수익 / 인벤토리 판매 수익 / 순이익 / 최종 자금을 표시한다.
* 영업 평가는 최근 주간 주문 결과를 이용하고 다음 주 신규 주문 수와 난이도 등장 비율에 반영한다.

### 가계부

* MVP 가계부는 기존 `SettlementModel.WeeklySettlements`를 원본으로 사용하는 주간 기록만 제공하고 일일 기록 모아보기는 확장 범위로 둔다.
* 주간 결산 표시 데이터 생성 흐름을 재사용하며 별도 경제 / 주문 / 평가 계산을 만들지 않는다.
* 목록은 최신순으로 표시하고 주차 / 주간 평가 / 총수입 / 총지출 / 순이익을 사용한다.
* 선택 상세는 기존 주간 결산과 같은 기간 / 시작과 종료 자금 / 운영 / 주문 결과 / 평가 / 경제 / 다음 주 변화 / 구매 상품 / 사용 파츠 / 직원 현황을 읽기 전용으로 표시한다.
* 경제 상세는 주문 / 판매 / 기타 수입과 상점 구매 / 빠른 재입고 / 정비비 / 고용비 / 주급 / 기타 지출 / 총수입 / 총지출 / 순이익을 구분한다.
* 운영과 주문 상세는 제작 완료와 할당량 / 배송 출발과 도착, 대기, 배송 중 / 정상과 지연 / 거절, 취소, 실패를 표시하고 평가는 주간 점수 / 자료 부족 / S, A, B, C, D 분포 / 주요 요구 달성률을 표시한다.
* 구매 상품과 사용 파츠는 이름 / 수량 / 지출 또는 `BasePrice` 합계를 표시한다.
* 직원 현황은 해당 주간 결산 시점의 고용 직원 수와 지급 주급을 포함하고, 과거 직원 수는 현재 `EmployeeModel`을 다시 조회하지 않고 `WeeklySettlementData`에 저장한 스냅샷을 사용한다.
* 리치 회계사를 고용하면 직원별 비례 주급 합계에 0.9 배율을 한 번 적용한 최종 주급을 기록하고 결산한다.
* 전체 누적 지출과 누적 이익은 주간 목록 상단 요약으로 추가할 수 있으나 MVP 필수 항목은 아니다.
* 가계부는 일반 닫기 / 지난 주차 선택만 제공하고 날짜 증가 / 다음 영업일 전환 / 결산 확정을 호출하지 않는다.
* 목록 화면은 이전 / 다음 버튼으로 월을 이동하고 상세 화면에서는 같은 버튼으로 결산 항목을 이동하며, 별도 돌아가기 버튼은 현재 목록 복귀 / 닫기 버튼은 가계부 전체 종료만 담당한다.
* 가계부 상세는 주간 결산의 구역별 슬롯 표시 데이터를 재사용하고 `결산 요약 -> 운영 현황 -> 주문 결과 -> 주문 평가 -> 경제 현황 -> 구매 상세 -> 소비 파츠 상세 -> 직원 현황 -> 다음 주 변화` 순서로 한 구역씩 표시한다.
* 가계부 상세 제목은 현재 결산 구역 이름을 `[ 결산 요약 ]` 형식으로 표시하고, 각 값은 아이콘과 수입 / 지출 색상을 적용한 개별 슬롯으로 표시한다.
* 결산과 가계부의 공용 결산 아이콘은 `SettlementIconData` 에셋 한 곳에서 종류별 Sprite를 관리하고 두 View가 같은 에셋을 참조한다.

#### 가계부 구현 계획

1차 구현 / 목록 데이터 Play Mode 확인 완료

* `WeeklySettlementData`에 결산 당시 고용 직원 수를 저장하고 기존 주간 결산 원본 / 표시 데이터 생성 흐름을 재사용한다.
* 연도 / 월 Dropdown은 오름차순으로 표시하고 이전 / 다음 버튼은 연도 경계를 포함해 이전 월 / 다음 월로 이동한다.
* 선택 월에 속한 완료 / 미결산 주차를 고정 슬롯에 함께 표시하며 완료 기록만 읽기 전용 상세를 열 수 있다.

### 1차 주간 영업 평가

* 아래 수치는 주간 결산 1차 구현과 플레이 테스트 기준이며 최종 밸런스 확정값이 아니다.
* 평가 대상은 해당 7일 동안 정상·지연 배송 / 직접·자동 거절 / 주문 취소 / 최종 실패로 종료된 주문이다.
* 진행 중 / 제작 완료 / 배송 대기 / 배송 중 주문은 종료된 주간의 평가 대상에 포함하지 않는다.
* 정상 배송의 주문별 평가 점수는 S 100 / A 85 / B 70 / C 45 / D 20을 사용한다.
* 지연 배송은 같은 등급 정상 배송 평가 점수의 70%를 적용한다.
* 배송하지 않은 종료 결과는 직접 거절 35 / 자동 거절 25 / 주문 취소 10 / 최종 실패 0점을 사용한다.
* 주간 평가 점수는 `평가 대상 주문 점수 합계 / 평가 대상 주문 수`로 계산한다.
* 평가 대상 주문이 7건 미만이면 통계는 표시하되 `자료 부족`으로 처리하고 다음 주 주문 수와 난이도 가중치 보정을 적용하지 않는다.

| 주간 평가 | 점수 | 다음 주 일일 주문 수 보정 | Easy / Normal / Hard 가중치 |
| --- | ---: | ---: | ---: |
| 최상 | 90 이상 | +1 | 5 / 5 / 3 |
| 우수 | 75 이상 | 0 | 6 / 5 / 2 |
| 보통 | 60 이상 | 0 | 7 / 4 / 2 |
| 주의 | 40 이상 | -1 | 8 / 4 / 1 |
| 위험 | 40 미만 | -1 | 9 / 3 / 0 |

* 아직 해금되지 않은 난이도는 주간 가중치와 관계없이 생성 후보에 포함하지 않는다.
* 주간 보정은 다음 7일 동안 적용하고 단기 주문량 페널티와 함께 최종 예상 주문 범위를 TopBar 알림에서 구분해 표시한다.
* 주간 보정과 단기 페널티 적용 후에도 수락 대기 목록이 가득 찬 경우가 아니면 신규 주문 최소 1개를 보장하는 방향으로 테스트한다.

### 결산 UI 1차 구성

* 자동 영업 종료 결산은 공용 `SettlementView` 아래의 `DailyContent` / `WeeklyContent`를 전환하는 구조로 구성하고 과거 내역 조회용 `가계부` 화면과 분리한다.
* 결산 패널은 뒤쪽 메인 UI 입력을 차단하고 일반 닫기 버튼 없이 일일 결산의 `다음 날` / 주간 결산의 `확인` 입력만 제공한다.
* 7일째에는 일일 결산 확인 후 같은 결산 View의 주간 페이지를 순서대로 표시하고 주간 결산 확인 뒤 다음 날로 진행한다.
* 공용 타이틀은 `일일 결산 / 월 일`과 `주간 결산 / 제N주`를 구분하고 확인 입력 시 현재 Content를 최하단까지 부드럽게 이동한 뒤 결산 확정을 전달한다.
* 확인 스크롤은 날짜별 재표시 전에 이전 트윈과 위치를 초기화해 매 결산에서 같은 속도로 반복한다.
* 기본 `SettlementSlotView`는 아이콘 / 묘사 문구 / 수입·지출 색상만 담당하고 `SettlementProgressSlotView`가 진행 바 표시와 재사용 초기화를 상속 확장한다.
* 결산 표시 데이터는 페이지 Builder와 슬롯 Builder로 분리하고 일일 / 주간 페이지가 구역 순서만 조합하며 각 구역의 개별 슬롯 문구 / 아이콘 / 진행률 생성은 슬롯 Builder가 담당한다.
* 일일 / 주간 Content는 구역 배치용 바깥 자동 레이아웃 / 구역 타이틀과 슬롯 Content를 배치하는 중간 레이아웃 / 실제 슬롯을 정렬하는 안쪽 레이아웃으로 나누고 동적 생성 뒤 안쪽에서 바깥쪽 순서로 크기를 갱신한다.

### 영업일 / 결산 시스템 1차 완료 상태

#### 영업 종료와 기록

* 할당량 달성 / 수락 대기와 Production 주문 소진의 두 종료 사유에서 결산 요청이 한 번만 발생하는지 확인한다.
* 제작 / 배송 출발 / 배송 도착 / 구매 / 판매 / 빠른 재입고 성공 기록은 한 번만 누적되고 실패 / 원상 복구 처리와 화면 재진입은 기록을 늘리지 않는지 확인한다.
* 영업 종료 시 오늘 도착 배송이 주문 기한 처리보다 먼저 완료되고 도착한 주문의 대금과 평가가 당일 기록에 포함되는지 확인한다.
* 결산 확정 전에 주문 기한·자동 거절·최종 실패가 반영되고 당일 주문 결과와 자금이 결산 수치와 일치하는지 확인한다.

#### 다음 영업일

* 결산 확인 후 날짜 증가 -> 주문 기한·페널티 하루 경과 -> 일반 재입고 -> BusinessDayModel 초기화 -> 새 DailyRecord 시작 -> 신규 주문 생성 순서가 한 번만 실행되는지 확인한다.
* 전날 Production / Crafted / Shipping 주문은 유지되고 오늘 제작 완료 수 / 빠른 재입고 횟수 / 당일 기록만 초기화되는지 확인한다.
* `RestockSpan` 1일 상품과 2일 이상 상품을 준비해 `(TotalDay - 1) % RestockSpan == 0` 날짜에만 재입고되는지 검증한다.
* 신규 주문 3~5개 / 주문량 페널티 / 주간 보정이 함께 적용돼도 최소·최대 범위를 벗어나지 않는지 확인한다.

* TopBar 날짜·자금·제작 진행률 / 상점 재고 / 주문 목록 / 일일 결산의 최종 값이 같은 런타임 상태를 표시한다.
