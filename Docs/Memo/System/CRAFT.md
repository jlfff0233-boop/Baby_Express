# CRAFT

## PURPOSE

아기 제작 / 파츠 배치 / 제작 코스트 / 테마 / 시너지의 기획과 미결정 사항을 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 주문 조건 원본은 [ORDER.md](ORDER.md) / 평가 반영은 [DELIVERY.md](DELIVERY.md) / 파츠 소비는 [INVENTORY.md](INVENTORY.md)와 연결한다.

## CONFIRMED

확정 규칙

### 제작 기본

* 제작은 플레이어가 발주해 인벤토리에 보유한 파츠만 사용한다.
* 주문 하나당 제작물 하나를 연결하고 제작 완료 후에는 파츠를 수정할 수 없다.
* 주문 취소 시 제작물을 폐기하고 소비한 파츠는 복구하지 않는다.
* [ORDER.md](ORDER.md)에 정의된 최소 제작 조건을 제작 확정 전에 검사하고 미충족 시 제작 확정을 막으며 파츠를 소비하지 않는다.
* 모든 파츠는 제작 코스트를 가지고 주문마다 최대 제작 코스트가 있다.
* 파츠 추가 시 현재 코스트와 추가 코스트의 합이 주문의 최대 제작 코스트를 초과하면 배치를 막고, 제작 확정 전에도 최대 제작 코스트 충족 여부를 다시 검사한다.
* 최소 제작 조건을 충족해 제작을 확정하면 조립 완성 점수를 한 번 적용한다.
* 파츠를 많이 붙였다는 이유만으로 추가 점수를 주지 않고 조립 완성 / 주요 요구 / 희망 / 테마 시너지로 점수를 얻는다.
* 남은 제작 코스트에는 별도 점수를 주지 않는다.
* 동일 시너지는 기본적으로 한 번만 반영해 반복 부착 악용을 막는다.

### 제작 런타임 데이터

* PlacedPartData는 같은 파츠를 여러 개 배치해도 개별 대상을 구분하도록 고유 배치 번호 / 파츠 데이터 / BabyBuildArea 기준 로컬 위치 / 회전 / 균등 스케일 / 저장 앞뒤 순서 인덱스를 보관한다.
* 루트 몸통 여부는 PlacedPartData에 중복 저장하지 않고 CraftModel의 루트 몸통 배치 번호를 단일 원본으로 사용한다.
* 1차 CraftModel은 선택 주문과 현재 배치 상태만 관리하며 주문별 제작물 결과 저장과 제작 확정 중복 차단은 제작 확정 통합 단계에서 구현한다.
* CraftActionResult는 배치 상태 변경의 성공과 실패만 표현하고 확정된 제작 점수 결과와 같은 결과 타입으로 섞지 않는다.

### 제작 MVP 책임

* CraftModel은 선택 주문과 실제 배치 상태 / 루트 몸통 / 배치 수량 / 현재 코스트를 관리하고 View 오브젝트와 현재 선택 상태를 참조하지 않는다.
* CraftPresenter는 현재 선택한 배치 번호를 보관하고 파츠 슬롯 / 배치 파츠 / 빈 제작 영역 입력을 받아 Model 호출과 담당 View 갱신을 중재한다.
* CraftView는 CraftListPanel과 CraftPanel 전환 / BabyBuildArea / PlacedPartsRoot / 배치 PartsView 생성·제거·선택 표시 / 빈 영역·뒤로가기·나가기 입력 / 제작 화면의 공용 표시와 패널 동작을 담당한다.
* CraftListView는 Production 주문 슬롯 목록 / 선택 주문 강조 / 제작 시작 / 목록 종료 입력을 담당한다.
* PartsView는 배치 파츠 하나의 이미지 / 위치 / 회전 / 균등 스케일 / 임시 앞 표시 / 선택 강조를 표현하고 클릭·드래그·선택 파츠 휠 입력을 전달한다.
* PartsSelectView는 파츠 선택 목록 표시 / 패널 입력 전달 / 자기 패널 위치 변경을 담당한다.
* UsedPartsListView와 CraftOrderDetailView는 각각 사용 파츠 목록 / 선택 주문의 주요 요구·희망 표시만 담당한다.
* CraftInfoPanelView는 공용 제작 정보 패널의 열기·닫기 입력과 위치 / 주문 상세·사용 파츠·테마 점수 Content 전환 / 버튼 문구를 담당한다.
* CraftView는 공용 제작 정보 패널의 열림 상태를 중재하고 제작 화면 진입 시 닫힘·주문 상세 Content로 초기화한다.
* CraftPresenter는 선택 주문의 조건을 표시 문자열로 변환해 CraftOrderDetailView에 전달한다.
* View는 CraftModel이나 InventoryModel을 직접 참조하지 않고 Presenter가 전달한 값만 표시한다.

### 제작 UI와 진입

* 주문 상세의 제작 바로가기는 해당 주문을 선택한 제작 화면 / 메인 제작 버튼은 제작 가능한 주문 목록을 열며 두 진입 방식은 같은 CraftModel / CraftPresenter / CraftView를 사용한다.
* 주문을 선택하지 않은 상태에서는 파츠 배치와 제작 확정을 진행할 수 없다.
* 제작 주문 슬롯은 Production 상태 주문만 표시한다.
* 제작 주문 목록의 기본 정렬은 납품 기한이 가까운 순이다.
* 제작 주문 목록은 마감일 빠른 순 / 마감일 늦은 순 / 특수 주문 상단 / 일반 주문 상단 정렬을 제공하며 특수·일반 우선 정렬 안에서는 주문 번호가 빠른 순으로 표시한다.
* 제작 목록에 들어올 때마다 기존 목록 선택을 초기화하며 플레이어가 주문을 직접 선택하기 전에는 제작 시작을 비활성화한다.
* 주문 화면과 제작 목록은 같은 OrderSlotView와 공용 프리팹을 사용하고 선택한 슬롯은 외곽선으로 강조하며 주문 선택 전에는 제작 시작 버튼을 비활성화한다.
* 제작 UI는 제작 주문 목록 / 실제 제작 화면 / 제작 완료 결과 패널로 구성하고 제작 화면에는 BabyBuildArea / 선택 주문 정보와 요구·희망·코스트 / 파츠 선택·사용 목록 패널 / 뒤로가기·제작 완료 입력을 둔다.
* 인벤토리 파츠 선택 패널과 제작 정보 패널은 사이드에서 접고 펼칠 수 있으며 각 패널 View는 입력 전달과 자기 위치 변경 / CraftView는 열림 상태 중재를 담당한다.
* 제작 정보 패널 하나에서 주문 상세 / 사용 파츠 / 테마 점수 Content를 전환하며 패널의 열림·닫힘 상태는 Content와 관계없이 함께 유지한다.
* 제작 정보 패널은 공용 열기·닫기 버튼 하나와 Content 전환 버튼 하나를 사용하고 현재 Content에 따라 다음 Content 문구를 표시한다.
* 주문 상세 Content는 현재 선택한 주문의 주요 요구 정확 수량과 희망 최소 수량을 표시한다.
* 주문 상세의 요구·희망은 주문 선택 시 갱신하고 사용 파츠 목록은 현재 보이지 않는 상태에서도 배치 변경에 맞춰 계속 갱신한다.
* 제작 본체의 뒤로가기는 선택 주문과 현재 배치를 유지한 채 제작 주문 목록으로 이동하고 제작 목록의 나가기는 제작 화면 전체를 닫는다.
* 실제 배치 파츠는 공용 PartsView 프리팹 하나를 사용하고 파츠별 PartsData.Icon / 위치 / 회전 / 균등 스케일 / 앞뒤 순서를 적용한다.
* 사용한 파츠 목록 패널은 PartType별 고정 Text에 해당 타입의 사용 파츠를 여러 줄로 표시하고 사용하지 않은 타입은 숨긴다.
* 파츠 선택 슬롯에는 인벤토리 보유 수량에서 현재 배치 수량을 뺀 배치 가능 수량을 표시하고 0개가 되면 추가 배치를 막는다.
* 루트 몸통이 배치된 뒤에도 다른 몸통을 확인하고 교체할 수 있도록 몸통 선택 슬롯은 계속 표시한다.
* PC 파츠 선택 슬롯에 포인터를 올리면 파츠 테마와 제작 코스트를 표시하며 슬롯의 TooltipPoint와 Canvas의 공용 TooltipView 하나를 사용하고 화면 경계를 넘으면 안쪽으로 위치를 보정한다.
* 제작 중 배치는 인벤토리 수량을 예약하거나 차감하지 않고 제작 확정 통합 단계에서만 실제 소비한다.
* 제작 미리보기와 제작 완료 패널에는 주요 요구별 달성·미달성 / 희망별 달성·미달성 / 활성·완성 테마 / 감점·보정 내역 / 예상 또는 최종 제작 점수만 표시한다.
* 제작 완료 패널의 주요 요구 / 희망 / 특수 조건은 각각의 고정 슬롯 목록으로 표시하고 주요 요구와 희망은 아이콘 / 설명 / 달성 개수 / 진행 바를 갱신한다. 특수 조건 문구의 괄호 상세는 줄바꿈해 자동 글자 크기가 과도하게 작아지지 않게 한다.
* 활성 테마 구역은 실제 활성 테마 수만큼 고정 슬롯을 활성화하고 테마 완성 여부에 따라 활성 체크 아이콘을 표시한다.
* 점수 보정 구역은 완성 테마의 점수 보정을 표시하고 상극일 때 아이콘과 보정 Text를 상극 값으로 교체한다. 상극 합계는 점수 체크 아이콘과 Text에도 반영하고 최종 제작 점수와 구분한다.
* 최소 제작 조건 / 사용 파츠 목록 / 현재 코스트는 제작 화면 본체에서 확인하고 제작 완료 패널에 반복 표시하지 않는다.
* 제작 등급은 제작 시스템에서 계산하거나 표시하지 않고 [DELIVERY.md](DELIVERY.md)의 배송·평가 단계에서 결정한다.
* 제작 완료 패널은 확인 / 주문으로 이동 입력을 제공한다.
* 제작 확정 실패 사유는 별도 안내 패널을 만들지 않고 제작 화면 실패 안내 Text에 표시하며 현재 배치 상태는 유지한다.

### 제작 점수

* 최종 제작 점수는 조립 완성 + 주요 요구 충족 - 주요 요구 미충족 + 희망 사항 충족 + 테마 시너지로 구성하며 0점 미만으로 내려가지 않는다.
* 주요 요구는 조건별로 충족 시 가산 / 미충족 시 직접 감점하고 등급 상한으로 대신하지 않는다.
* 희망 사항은 미충족 감점 없이 충족한 조건만 가산한다.
* 제작 확정 전에도 실제 제작 확정과 같은 계산 규칙으로 예상 점수 / 항목별 성공과 실패 / 변경 전후 차이를 표시한다.
* 제작 점수 원점수와 항목별 증감은 보존하고 최종 합계에만 0점 하한을 적용한다.

#### 프로토타입 초기 수치

* 조립 완성 +100 / 주요 요구 충족 개당 +100 / 주요 요구 미충족 개당 -100 / 희망 사항 충족 개당 +40을 초기값으로 사용한다.
* 일반 테마 +60 / 완성 테마 +140 / 목표 테마 1.5배 / 상극 한 쌍 -40을 초기값으로 사용한다.
* 활성 테마 1개는 합계 100% / 2개는 85% / 3개 이상은 70% 감쇠를 초기값으로 사용한다.
* 일반 주문 테마 상한 200 / 목표 테마 주문 테마 상한 250을 초기값으로 사용한다.
* 위 수치는 확정 밸런스가 아니며 주요 요구 -100이 지나치게 가혹하면 -50과 비교 테스트한다.

#### 파츠 제작 코스트 1차 후보

* 제작 코스트는 단순 1 / 보통 2 / 복잡 3 / 특수 4의 작은 정수 티어를 사용한다.
* PartType별 후보는 Body `2~3` / Eye `1~2` / Nose `1` / Mouth / Arms / Legs `1~2` / Hair / Tail / Claws `2~3` / Wings / Horns `2~4`이다.
* 실제 값은 가격이 아니라 파츠 디자인 복잡도와 주문 구성 선택지를 기준으로 정하며 `BasePrice`와 자동 비례시키지 않는다.
* 12종 파츠별 1차 CraftCost와 상품 ID는 [SHOP.md](SHOP.md)의 `12종 파츠 1차 데이터`를 단일 원본으로 사용한다.
* 파츠 희귀도는 점수 / 해금 / 가격 / 재고 / 연구 / 제작 코스트와 역할이 겹치므로 데이터와 제작 판정에서 제거하고 새 점수 요소로 추가하지 않는다.

#### 점수 예시

* 조립 완성 +100 / 주요 요구 2개 중 1개 충족과 1개 미충족으로 +100 -100 / 희망 2개 중 1개 충족으로 +40 / 테마 +60이면 최종 제작 점수는 200이다.
* 주요 요구 미충족으로 원점수가 -40이면 항목별 -40은 결과에 남기고 화면의 최종 제작 점수는 0으로 표시한다.
* 난이도마다 주요 요구와 희망 개수가 다르므로 같은 절대 점수 구간으로 등급을 정하지 않고 주문 목표 점수 달성률 또는 난이도별 기준은 [DELIVERY.md](DELIVERY.md)에서 결정한다.

### 테마 데이터

* 테마는 종족 테마와 성질 테마로 구분하며 두 종류 모두 기존 테마 시너지 계산 대상이다.
* 종족 테마는 `Slime / Werewolf / Vampire / Bicorn / Gargoyle / Imp / Kraken / Mandragora / Ghost / Mushroom / Goat / Moth` 12종으로 구성하고 사이클롭스는 자유로운 동일 타입 복수 부착 구조와 맞지 않아 사용하지 않는다.
* 성질 테마는 `말랑 / 복슬 / 뾰족 / 둥근 / 단단 / 반짝 / 미끌` 7종을 1차 방향으로 유지하고 `묵직 / 장난 / 몽환`은 사용하지 않는다.
* 상극은 `말랑 <-> 단단` / `뾰족 <-> 둥근` / `복슬 <-> 미끌` 3쌍을 사용하며 반짝은 현재 상극이 없다.
* 실제 enum 일괄 변경과 파츠별 성질 테마 대량 입력은 이미지와 분포 검증이 끝날 때까지 보류한다.
* 말랑은 물렁하거나 탄성 있는 재질 / 복슬은 털·솜·보풀 / 뾰족은 뾰족한 실루엣 / 둥근은 둥근 덩어리감 / 단단은 돌·뿔·발굽·각질·갑각 / 반짝은 실제 광택·발광·보석성 / 미끌은 젤·점액·젖은 피부가 이미지에 명확할 때만 부여한다.
* 단순한 곡선이나 귀여운 인상만으로 둥근 / 말랑을 붙이지 않고 Eye / Nose / Mouth도 특징이 명확하지 않으면 성질 테마를 부여하지 않는다.
* 같은 종족 파츠를 여러 PartType에 걸쳐 조합하면 종족 테마 / 여러 종족 파츠가 공유하는 성질을 맞추면 성질 테마를 활성화할 수 있다.
* 종족 테마와 성질 테마가 동시에 조건을 만족하면 각각 활성 테마로 계산하며 데이터에서는 두 테마 종류를 구분한다.
* 파츠 하나는 복수 테마를 가질 수 있고 PartsData는 테마 원본 데이터만 제공한다.
* 늑대 꼬리의 Werewolf + 복슬처럼 파츠 하나에 종족 테마와 성질 테마를 함께 배정할 수 있으며 구체적인 성질 조합은 실제 파츠 이미지 확정 후 갱신한다.
* 테마 시너지는 오믈렛에 넣을까요?의 태그 조합형 시너지를 주문 제작 구조에 맞게 축소 적용한다.
* 레퍼런스의 파츠 자체 점수 / 위치와 접촉 배수 / 상태 전파 / 전체 제작 점수 배수는 사용하지 않고 복수 테마 조합 / 완성 테마 / 목표 테마 보정 / 감쇠 / 상극만 반영한다.

### 테마 시너지

* 제작에 사용한 서로 다른 PartType 중 같은 테마를 가진 타입이 절반을 초과하면 일반 테마 시너지를 활성화한다.
* 분모는 테마가 없는 파츠를 포함해 제작에 실제 사용한 모든 서로 다른 PartType 수이다.
* 같은 타입의 파츠를 여러 개 사용해도 테마별 달성 타입 수에는 한 번만 반영하며 같은 타입의 서로 다른 파츠가 서로 다른 테마를 가지면 각 테마에서 해당 타입을 계산할 수 있다.
* 사용한 모든 서로 다른 파츠 타입이 같은 테마에 포함되면 완성 테마 / 절반을 초과하면 일반 테마를 적용하고 정확히 절반이면 활성화하지 않는다.
* 말랑과 동글처럼 복수 테마가 한 제작물에서 동시에 활성화될 수 있다.
* 활성 테마 점수 합계에 활성 테마 수 기준 감쇠를 한 번 적용하고 주문 종류에 맞는 상한을 적용한다.
* 상극 테마가 동시에 활성화되면 테마 시너지에서만 감점하고 주요 요구 / 희망 / 배송 점수는 직접 깎지 않는다.
* 상극 감점 후 테마 시너지는 0 아래로 내려가지 않는다.
* 상극은 양방향을 같은 한 쌍으로 보고 활성화된 한 쌍당 한 번만 감점한다.
* 주문이 활성 테마를 요구한 경우 테마 시너지와 주문 조건 점수를 각각 반영한다.

### 테마 연구 보너스

* 정비의 테마 연구는 성질 테마만 강화하고 종족 테마에는 별도 연구를 두지 않는다.
* 성질 테마별 연구 보너스는 `Lv.1 +10 / Lv.2 +20 / Lv.3 +30`의 현재 단계 최종값을 사용하며 단계값을 누적 합산하지 않는다.
* 활성 테마의 `기본 점수 + 목표 테마 보너스 + 연구 보너스`를 테마 소계로 사용한 뒤 기존 복수 테마 감쇠 -> 일반·목표 상한 -> 상극 감점 -> 0점 하한 순서를 유지한다.
* 목표 테마 보정은 연구 보너스를 다시 증폭하지 않으며 연구 보너스도 기존 감쇠 / 상한 / 상극의 영향을 받는다.
* `CraftThemeResult`에는 테마별 연구 보너스 / `CraftScoreResult`에는 전체 연구 보너스를 기존 점수와 구분해 보존하고 제작 예상·결과 UI에서 증가 원인을 표시한다.
* 정비는 테마 연구 단계와 최종 보너스를 제공하고 실제 활성 여부와 점수 계산은 `CraftReviewModel`이 담당한다.

### 악마 아기 종족과 파츠 구성

* 아기는 종족별 실제 신체 비례를 그대로 재현하지 않고 머리와 몸이 이어진 동글동글한 공통 아기 체형을 사용하며 색 / 재질 / 얼굴 / 팔다리 / 연구 파츠로 종족을 구분한다.
* 2D 카툰과 작은 이미지의 실루엣 가독성을 우선하며 기본 `Body / Eye / Nose / Mouth / Arms / Legs`는 연구로 잠그지 않는다.
* 연구 확장 PartType은 `Hair / Wings / Tail / Claws / Horns`이며 각 종족의 특징적인 외형을 단계적으로 해금한다.

| 종족 | 기본 방향 | 연구 확장 파츠 |
| --- | --- | --- |
| 슬라임 | 기본 6타입 / 혼합 제작 베이스 | 없음 |
| 늑대인간 | 기본 6타입 | Hair 갈기·털 / Tail 늑대 꼬리 |
| 뱀파이어 | 기본 6타입 / 송곳니는 Mouth / Hair·Claws 미사용 | Wings |
| 바이콘 | 기본 6타입 / 발굽형 사지 | Hair 갈기 / Tail 말형 꼬리 / Horns 두 뿔 |
| 가고일 | 기본 6타입 / 돌 재질 Body | Wings / Horns / Claws / Tail |
| 임프 | 기본 6타입 / 붉은 Body와 얼굴 | Horns / Tail |
| 크라켄 | Body / Eye / Nose / Mouth / 촉수형 Legs / Arms 미사용 | 없음 |
| 만드라고라 | 기본 6타입 / 인간형 사지 | Hair 잎·꽃 / Tail 덩굴 |
| 고스트 | Body / Eye / Nose / Mouth / 인간형 Arms / 영혼 하체는 Body / Legs 미사용 | 없음 |
| 버섯 악마 | 기본 6타입 / 인간형 사지 | Hair 보류 |
| 염소 악마 | 기본 6타입 / 발굽형 사지 | Hair 짧은 털 / Tail 짧은 꼬리 / Horns 말린 뿔 |
| 나방 악마 | Body / Eye / Nose 또는 Mouth / 곤충형 Arms·Legs | Hair 더듬이·목털 / Wings 나방 날개 / Claws 곤충 발톱 |

* `Hair`는 털 / 갈기 / 잎 / 꽃 / 더듬이·목털, `Tail`은 꼬리 / 덩굴, `Wings`와 `Horns`는 종족별 형태를 같은 조립 역할 안에서 표현한다.
* 크라켄 피부 무늬와 고스트 영혼 하체처럼 별도 조립 역할이 없는 외형은 Body 이미지에 포함하고 한 종족만을 위해 Pattern / Plant / MushroomCap 같은 PartType을 추가하지 않는다.
* ArmType / LegType은 `None / Human / Hoofed / Paw / Pinnipeds / Insect` 방향으로 사용하고 종족 하나 때문에 새로운 PartType을 추가하지 않는다.
* 인간형은 뱀파이어 / 임프 / 만드라고라 / 고스트 / 버섯 악마, Hoofed는 바이콘 / 염소 악마, Paw는 늑대인간, Pinnipeds는 크라켄, Insect는 나방 악마에 사용한다.

#### 테마 판정 예시

* 몸통 / 눈 / 코 / 입 / 뿔 5타입 중 3타입이 말랑이면 일반 시너지 +60 / 동글 완성 +140과 뾰족 일반 +60이 함께 활성화되면 2테마 감쇠 85%로 170 / 두 테마가 상극이면 -40을 적용해 130이다.
* 상극을 상한 전에 적용하면 상한 초과분에 감점이 묻힐 수 있으므로 상한 적용 후 상극을 감점한다.

### 자유 조립과 부착

* 고정된 눈 / 코 / 입 소켓을 사용하지 않고 몸통 주변의 넓은 부착 가능 영역에서 타입과 관계없이 파츠를 자유롭게 배치한다.
* 눈과 입의 복수 장착 / 같은 파츠 중복 / 비대칭 / 몸통 가운데 뿔 / 일부러 삐뚤거나 일반적이지 않은 위치의 배치를 허용한다.
* 몸통은 제작물에 동시에 정확히 하나만 배치할 수 있으며, 해당 몸통을 제작물 좌표와 전체 부착 가능 영역의 기준인 루트 몸통으로 사용한다.
* 루트 몸통은 중앙 생성 위치와 기본 스케일 4.5로 고정하고 이동·크기 변경하거나 다른 파츠보다 앞으로 표시하지 않는다.
* 다른 몸통으로 교체해도 몸통 외에 이미 배치한 파츠는 유지한다.
* 파츠 전체가 영역 안에 있을 필요는 없고 파츠의 부착 기준점이 루트 몸통의 전체 부착 가능 영역 안에 있으면 유효하다.
* 추천 영역은 적합한 위치 / 앞뒤 레이어 / 배치 범위를 안내할 뿐 이탈을 막거나 점수를 감점하지 않는다.
* 자유 배치는 외형 제작의 재미 / 테마 조합은 제작 코스트 안에서 점수를 최적화하는 시스템적 재미로 분리하며 위치와 접촉은 점수에 사용하지 않는다.
* 자유 배치 파츠는 타입별 Group으로 나누지 않고 BabyBuildArea 아래 PlacedPartsRoot 하나에서 전체 앞뒤 순서를 관리한다.
* 파츠 슬롯을 선택하면 BabyBuildArea 중앙 부근의 순환 위치에 파츠를 생성하고 생성한 파츠를 즉시 선택한다.
* 파츠 크기는 X / Y를 따로 변경하지 않고 균등 스케일 하나로 조절하며 파츠 수량 / 제작 코스트 / 테마 판정에는 영향을 주지 않는다.

### 파츠 배치와 입력

* 파츠 슬롯 선택 -> 인벤토리 보유 수량과 현재 배치 수량 확인 -> 중앙 부근 생성 위치 계산 -> CraftModel.AddPart -> PartsView 생성 -> 새 배치 파츠 선택 -> 파츠 슬롯 / 사용 목록 / 현재 코스트 갱신 순서로 처리한다.
* 중앙 생성 위치는 완전한 무작위 대신 중앙 / 오른쪽 위 / 왼쪽 아래 / 오른쪽 아래 / 왼쪽 위처럼 작은 고정 오프셋을 순환해 같은 위치에 계속 겹치지 않게 한다.
* 루트 몸통이 없을 때 몸통 외 파츠를 선택하면 RootBodyRequired로 배치를 막고 최초 몸통을 루트 몸통으로 지정한다.
* 제작 영역은 Canvas UI이므로 RectTransform / EventSystem Pointer·Drag 입력을 사용하고 Rigidbody2D / Collider2D는 사용하지 않는다.
* 파츠끼리 겹칠 수 있으며 드래그 중인 파츠는 저장된 앞뒤 순서를 바꾸지 않고 임시로 가장 앞에 표시한다.
* 새 파츠를 생성하면 기존 선택 강조를 해제하고 새 배치 번호를 CraftPresenter의 현재 선택으로 저장한다.
* 배치 파츠를 클릭하면 해당 배치 번호를 다시 선택하고 BabyBuildArea의 빈 영역을 클릭하면 현재 선택을 해제한다.
* 선택된 파츠만 드래그할 수 있고 선택되지 않은 파츠의 드래그 입력은 배치 상태를 변경하지 않는다.
* 드래그 화면 좌표는 RectTransformUtility를 이용해 BabyBuildArea 기준 로컬 좌표로 변환하고 CraftModel.MovePart 성공 후 PartsView 위치에 반영한다.
* PartsView 루트 스케일은 1로 유지하고 파츠 균등 스케일은 CraftModel에 저장한 값이 성공적으로 변경된 뒤 Renderer의 localScale에 반영한다.
* PC에서는 선택된 PartsView 영역 위의 마우스 휠 입력으로 몸통 외 파츠의 균등 스케일을 0.1씩 변경하고 0.5~3 범위로 제한한다.
* 모바일에서는 선택된 몸통 외 파츠를 두 손가락 핀치로 균등 확대·축소하며 같은 프레임의 단일 포인터 드래그와 중복 처리하지 않는다. 실기기 검증을 완료했다.
* PC에서 몸통 외 배치 파츠를 우클릭하면 해당 파츠를 제거하고 루트 몸통을 제거하면 선택 주문은 유지한 채 전체 배치를 초기화한다.
* 배치 시 기본 스케일은 몸통 4.5 / 그 외 파츠 2를 사용한다.
* 이동과 크기 변경은 파츠 수량 / 제작 코스트 / 테마 상태를 변경하지 않는다.
* 신규 파츠는 작은 크기에서 나타나고 드래그 종료와 휠 입력 종료 후 탄성 있게 안착한다. 연속 입력 중에는 연출을 반복 생성하지 않으며 저장하는 파츠 균등 스케일과 시각 피드백용 루트 스케일을 분리한다.
* 몸통 교체와 저장 복구로 재생성한 파츠는 등장 연출 없이 현재 저장 상태로 즉시 표시한다.
* 파츠와 제작 결과의 파츠·테마 아이콘은 지정된 최대 표시 영역 안에서 원본 Sprite 비율을 유지한다.
* 제작 결과의 주요 요구 / 희망 / 특수 조건 / 활성 테마 슬롯 수가 홀수이면 해당 구역의 Empty 슬롯을 활성화해 마지막 줄 정렬을 보정한다.

#### 루트 몸통 예시

* 슬라임 몸통을 루트로 먼저 놓고 몸통 가장자리 밖으로 날개가 돌출되어도 날개의 부착 기준점이 전체 영역 안이면 배치할 수 있다.
* 루트 몸통이 이미 있으면 다른 몸통을 추가로 배치할 수 없고, 몸통 교체는 기존 몸통을 대체하되 다른 파츠를 유지한다.

### 배치 View 동기화와 갱신

* CraftView는 배치 번호별 PartsView를 조회할 수 있도록 배치 번호와 View의 대응 상태를 관리한다.
* PlacedPartData.PartIndex는 PlacedPartsRoot의 SiblingIndex와 같은 순서로 유지하고 영구 순서 변경 때만 CraftModel.SetPartIndex를 호출한다.
* 드래그 중 임시 앞 표시는 저장된 PartIndex를 변경하지 않고 드래그 종료 후 전체 PartsView를 저장 순서로 복구한다.
* 파츠 추가 / 일반 파츠 제거 / 루트 몸통 제거 / 전체 초기화 후 파츠 선택 슬롯의 남은 수량 / 사용 파츠 목록 / 현재 제작 코스트를 갱신한다.
* 위치 / 회전 / 균등 스케일 / 선택 강조만 바뀐 경우 사용 파츠 목록과 현재 제작 코스트를 다시 계산하지 않는다.
* 일반 파츠 제거 시 해당 PartsView와 선택 상태만 정리하고 루트 몸통 제거 시 선택 주문은 유지한 채 PlacedPartsRoot의 배치 View 전체를 제거한다.
* 배치 View를 재생성할 때는 CraftModel의 현재 배치 목록을 기준으로 복원하며 화면 오브젝트를 배치 상태의 원본으로 사용하지 않는다.

### 제작 결과와 판정 책임

* 제작물에는 주문 ID / 루트 몸통 배치 번호 / 파츠별 배치 번호와 ID·로컬 위치·회전·균등 스케일·앞뒤 순서 / 제작 코스트 / 점수 판정 결과를 보관한다.
* 점수 판정 결과는 최소 조건별 결과 / 주요 요구별 충족과 점수 / 희망별 충족과 점수 / 활성·완성 테마 / 감쇠 / 상극 / 원점수 / 최종 점수를 포함한다.
* 제작 중 미리보기와 제작 확정은 같은 계산 규칙을 사용하고 제작 확정 결과는 고정해 [DELIVERY.md](DELIVERY.md)의 최종 평가 입력으로 전달한다.
* Model이 최소 조건 / 코스트 / 주문 조건 / 테마 / 점수를 계산하고 Presenter는 호출과 표시 데이터 변환 / View는 전달받은 결과 표시만 담당한다.
* CraftReviewModel은 빈 배치와 미완성 배치도 주요 요구 / 희망 / 테마 / 예상 점수까지 계산하고 제작 가능 여부를 별도로 반환한다.
* 제작 판정은 최소 조립 조건 / 최대 제작 코스트 / 주요 요구 정확 수량 / 희망 최소 수량 / 테마 활성·완성 / 감쇠·상한·상극 / 전체 파츠 수·목표 테마·제외 테마 특수 조건을 계산한다.
* CraftReviewModel은 정비의 현재 성질 테마 연구 보너스를 조회해 기존 테마 판정에 합산하고 `CraftThemeResult`와 `CraftScoreResult`에 연구 보너스를 분리 보존한다.
* 제작 확정은 주문·중복·상태 사전 검증 -> 제작 재판정 -> 소비 파츠 전체 검증 -> 배치·판정 복사본 생성 -> 인벤토리 일괄 소비 -> 제작 결과 임시 등록 -> 주문 Crafted 전환 순서로 처리한다.
* 주문 상태 전환에 실패하면 임시 제작 결과를 제거하고 소비한 인벤토리를 복구해 인벤토리 / 주문 / 제작 결과에 부분 변경을 남기지 않는다.
* 확정 결과는 CraftModel의 편집 목록과 PlacedPartData를 직접 참조하지 않고 새 목록과 새 객체로 복사하며 PartsData 원본 참조만 유지한다.
* CraftReviewViewBuilder는 제작 판정 결과를 제작 완료와 배송 화면에서 공용으로 사용할 표시 데이터로 변환한다.
* 제작 완료 패널의 배송 입력은 완료 주문 ID를 배송 화면으로 전달하고 제작 화면을 닫는다.

### 판정 흐름

* 사용 파츠와 배치 확정 -> 최소 조건과 코스트 검사 -> 주요 요구와 희망 판정 -> 테마별 PartType 집계 -> 일반 / 완성 판정 -> 목표 테마 보너스와 성질 테마 연구 보너스 합산 -> 복수 테마 감쇠 -> 상한 -> 상극 감점 -> 테마 점수 0 하한 -> 최종 제작 점수 0 하한 순서이다.
* 소수점이 발생하면 중간마다 반올림하지 않고 전체 계산 마지막에 한 번만 처리한다.

### 제작 표현

* 제작은 몸통 파츠 위에 다른 파츠를 올리거나 부착하는 방식이다.
* 현재 기본 후보는 2D이며 로우폴리 실루엣 / 면 분할 / 제한 팔레트 / 단순 음영으로 3D 로우폴리 인상을 내는 방향을 검토한다.
* 실제 3D 제작은 모델 / 재질 / 카메라 / 조명 / 선택 판정 / 모바일 성능 비용이 커 확장 또는 보류 후보이다.

### PC 배치 통합 검증 기준

* 주문 미선택 상태에서 파츠 배치가 차단되는지 확인한다.
* 루트 몸통 전에는 몸통만 배치되고 최초 몸통이 중앙 부근에 생성되어 즉시 선택되는지 확인한다.
* 루트 몸통 배치 후에는 다른 몸통을 추가로 배치할 수 없는지 확인한다.
* 슬롯 선택을 반복해도 인벤토리 보유 수량을 초과해 배치할 수 없고 제작 확정 전 인벤토리 실제 수량은 바뀌지 않는지 확인한다.
* 현재 코스트와 추가 파츠 코스트의 합이 주문의 최대 제작 코스트를 초과하면 해당 파츠 배치가 차단되는지 확인한다.
* 새 파츠 선택 / 기존 파츠 재선택 / 빈 영역 선택 해제 / 선택된 파츠만 드래그 이동이 동작하는지 확인한다.
* 화면에 표시된 위치 / 회전 / 균등 스케일 / 앞뒤 순서와 CraftModel의 PlacedPartData가 일치하는지 확인한다.
* 드래그 중 임시 앞 표시가 저장된 PartIndex를 바꾸지 않는지 확인한다.
* 파츠 추가와 제거 후 선택 슬롯의 남은 수량 / 사용 파츠 목록 / 현재 제작 코스트가 함께 갱신되는지 확인한다.
* 루트 몸통 제거 시 배치 상태와 배치 View가 모두 초기화되고 선택 주문은 유지되는지 확인한다.
* 공용 제작 정보 패널의 주문 상세 / 사용 파츠 / 테마 점수 Content를 순환 전환할 수 있는지 확인한다.
* Content를 전환해도 공용 패널의 열림·닫힘 상태와 버튼 위치가 유지되는지 확인한다.
* 메인 제작 목록과 주문 상세 제작 바로가기에서 선택한 주문의 주요 요구·희망이 동일하게 표시되는지 확인한다.
* 주문 상세를 표시하는 동안 파츠를 변경한 뒤 사용 파츠 목록으로 돌아와도 최신 배치 내용이 표시되는지 확인한다.
