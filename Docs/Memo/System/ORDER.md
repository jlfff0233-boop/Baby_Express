# ORDER

## PURPOSE

주문 생성 / 수락 / 상태 / 기한 / 주문 UI / 페널티 / 특수 주문의 기획과 미결정 사항을 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 제작 판정은 [CRAFT.md](CRAFT.md) / 배송과 보상은 [DELIVERY.md](DELIVERY.md) / 영업 종료 호출 순서는 [DAY.md](DAY.md)를 따른다.

## CONFIRMED

확정 규칙

### 책임과 데이터

* CustomerOrder는 생성된 주문 하나의 일반 C# 런타임 데이터이다.
* CustomerOrderModel은 전체 주문 원본 / 상태별 조회 / 상태 전이 / 기한 / 수락 대기 제한을 담당한다.
* OrderGeneratorModel은 날짜 / 진행도 / 난이도 Pool / 해금 파츠 / 특수 주문을 조합하고 신규 주문 생성 흐름을 중재한다.
* OrderConditionGenerator는 주요 요구와 희망 생성 / 파츠 ID 중복 방지 / 최소 구성 자동 달성 방지를 담당하고 OrderGeneratorModel과 같은 Random을 공유한다.
* OrderCostCalculator는 주문 조건의 최소 해결 구성 / 최소 제작 코스트 / 최대 제작 코스트 계산만 담당하고 실제 제작물 점수는 계산하지 않는다.
* OrderPartCondition은 주요 요구와 희망을 함께 표현하는 공통 조건 데이터이며 Requirement는 주요 요구 / Wish는 희망에만 사용한다.
* OrderPresenter는 View 입력 / Model 호출 / ViewData 변환 / View 갱신만 담당하고 주문 판정과 보상을 계산하지 않는다.
* PlayScene은 주문 Model 생성과 Presenter 연결 / PlayStateModel은 현재 날짜와 영업 상태 제공을 담당한다.
* 난이도 / 생성 범위 / 기한 / 코스트 / 평가 조정값은 설정 데이터로 관리하고 생성된 주문은 생성 당시 값을 고정 보관한다.

### 주문 생성과 수락

* 하루 시작 시 신규 주문을 한 번에 생성한다.
* 수락 대기 목록은 기본 5개 / 업그레이드 최대 20개이며 아직 받지 않은 주문만 계산한다.
* 기본 일일 신규 주문 수는 3~5개를 균등 무작위로 정하고 실제 생성 수는 무작위 결과와 수락 대기 빈자리 중 작은 값으로 정한다.
* Easy / Normal / Hard 난이도 Pool 안에서 주요 요구 / 희망 / 파츠 / 개수 조건을 랜덤 조합한다.
* Easy는 처음부터 / Normal은 튜토리얼 완료 후 / Hard는 11종 파츠 타입이 모두 하나 이상 해금된 후 주문 생성 후보로 사용한다.
* 난이도 기본 가중치는 Easy 7 / Normal 4 / Hard 2이며 현재 해금된 난이도만 가중치 선택 후보에 포함한다.
* 주요 요구 수는 Easy `0~1` / Normal `1~2` / Hard `2~3`, 희망 수는 Easy `0~1` / Normal `1~3` / Hard `2~3`을 1차 기준으로 사용한다.
* 최대 제작 코스트는 Easy `8` / Normal `11` / Hard `15`의 고정값을 1차 기준으로 사용한다.
* 정상 납품 기한은 Easy `4~5일` / Normal `3~4일` / Hard `2~3일`, 지연 허용 기간은 Easy `4일` / Normal `3일` / Hard `2일`을 사용한다.
* 수락 가능 기간은 Easy `2~3일` / Normal `2일` / Hard `1일`을 사용한다.
* 주문은 난이도 선택 -> 해당 난이도 조건 생성 -> 해결 가능 여부 검사 순서로 생성한다.
* 생성한 주문의 최소 해결 코스트가 난이도별 최대 제작 코스트를 넘으면 해당 주문 생성을 재시도한다.
* 파츠 제작 코스트 1~4 체계에서는 고정 여유값 10과 10단위 올림을 사용하지 않는다.
* Easy는 연구 파츠 주요 요구와 목표 테마를 사용하지 않거나 매우 낮은 확률로 제한하고, Normal부터 연구 파츠 주요 요구와 목표 테마를 본격적으로 사용한다.
* Hard는 주요 요구 개수만 늘리기보다 목표 테마 / 희망 / 최대 제작 코스트 제한을 조합해 선택 최적화 난이도를 만든다.
* 생성 후보는 현재 해금된 파츠이며 현재 인벤토리 보유 수량은 반영하지 않는다.
* 상품 해금 상태는 PlayStateModel이 단일 원본으로 관리하고 OrderPresenter가 해금된 파츠만 OrderGeneratorModel에 전달한다.
* 튜토리얼 시스템 연결 전에는 Easy / Normal을 기본 후보로 사용하고 이후 Normal에 튜토리얼 완료 조건을 연결한다.
* 수락 대기 목록이 가득 차면 생성하지 않고 빈자리가 부족하면 빈자리만큼만 생성한다.
* 목록 만석으로 생성하지 못한 주문은 거절이나 페널티로 처리하지 않는다.
* 플레이어는 원하는 주문을 직접 받고, 받은 주문 수에는 하드 제한을 두지 않는다.
* 무리하게 받은 결과는 납품 기한 / 자금 / 재고 관리 위험으로 처리한다.
* 일일 제작 할당량은 하루 신규 주문 수 / 받은 주문 수와 다른 값이며 주문을 많이 받아도 제작 완료 가능한 수는 [DAY.md](DAY.md)의 할당량에 제한된다.
* 제작 할당량을 채워 자동 결산해도 수락 대기 / 진행 중 / 배송 대기와 배송 중 주문은 종료하지 않고 다음 날로 이월한다.
* 직접 거절과 자동 거절은 페널티를 적용하되 주문 취소와 최종 실패보다 약하게 적용한다.
* 수락 가능 기한은 주문별로 정하며 납품 기한보다 늦을 수 없다.
* Easy / Normal / Hard는 내부 난이도이고 VIP는 초반 미등장 특수 주문이다.

### 주문 조건

* 용어는 최소 제작 조건 / 주요 요구 사항 / 희망 사항 / 시너지로 구분한다.
* 최소 제작 조건은 몸통 / 눈 / 코 / 입 각각 1개이며 미충족 시 제작 완료와 납품이 불가능하다.
* 1차 주요 요구 사항은 구체적인 파츠 아이디 + 정확 수량 조건을 사용하고 지정 파츠가 정확히 n개인지 판정한다.
* 희망 사항은 주요 요구와 같은 조건 종류를 사용할 수 있지만 미충족 상태로 납품할 수 있고 충족 시 추가 평가 점수를 얻는다.
* 1차 희망 사항은 구체적인 파츠 아이디 + 최소 수량 조건을 사용하고 지정 파츠가 n개 이상인지 판정한다.
* 희망 사항은 이후 테마 / 특성 / 기타 조건으로 확장하고 주요 요구와 희망 사항의 전체 개수는 최대 12개로 제한한다.
* 주요 요구는 같은 파츠 아이디와 같은 PartType을 중복 사용하지 않으며 Body는 최소 제작에 필수이므로 자동 생성 대상에서 제외한다.
* Eye / Nose / Mouth도 최소 제작 조건과 의미가 겹치는 주요 요구는 가급적 피하고 Arms / Legs / Hair / Wings / Tail / Claws / Horns를 우선한다.
* 희망 사항은 같은 파츠 아이디 중복을 피하되 같은 PartType의 수량 표현은 허용할 수 있다.
* 주요 요구만 충족하거나 최소 제작 조건만 갖춘 상태에서 희망 사항이 자동 달성되는 조건은 생성하지 않는다.
* 최소 제작 조건은 파츠 타입별 전체 사용 수량 / 주요 요구와 희망 사항은 파츠 아이디별 사용 수량으로 판정한다.
* 지정 파츠가 몸통 / 눈 / 코 / 입이면 해당 수량을 최소 제작 조건에도 반영한다.
* 몸통은 하나만 배치할 수 있으므로 몸통 주요 요구와 희망 수량을 1개로 고정하고 한 주문에 몸통 조건을 중복 생성하지 않는다.
* 주문 생성 시 최소 제작 조건 / 주요 요구 / 희망 사항을 최대 제작 코스트 안에서 모두 만족할 수 있는지 검증한다.

### 식별자와 날짜

* 주문 ID는 Order_{생성 누적 영업일}_{누적 생성 주문 번호}_{난이도} 형식이다.
* 누적 생성 주문 번호는 주문 생성 때마다 증가하며 상태가 바뀌어도 변경하지 않는다.
* UI 주문 번호는 ID를 분해하지 않고 CustomerOrder.CreatedNumber를 표시한다.
* 생성일 / 수락 마감일 / 납품 마감일 / 최종 기한 판정은 누적 영업일을 사용한다.
* 생성 월 / 일은 중복 저장하지 않고 누적 영업일을 달력 규칙으로 변환한다.
* 주문 제목 원본은 OrderTitleData / 생성된 최종 제목은 CustomerOrder에 고정하며 기본 구조는 `수식구 + 요청 문구`를 유지한다.
* 일반 수식구 24개와 요청 문구 24개를 사용해 576개 조합을 만들고 긴급 / VIP 전용 수식구는 각각 10개 후보를 별도 풀로 둘 수 있다.
* 난이도별 제목 풀은 만들지 않고 긴급성과 VIP만 제목 톤에 반영하며 최근 5~10개 최종 제목과 완전히 같은 조합은 제한 횟수 안에서 재추첨한다.
* 최근 제목 목록은 런타임 세션 또는 현재 주문 풀에서만 관리하고 저장 데이터에는 추가하지 않는다.

### 진행과 기한

* 제작 진행 상태 / 기한 상태 / 최종 결과를 분리해 연체되어도 제작 진행 상태를 유지한다.
* 제작 진행은 수락 대기 / 해결 필요 / 제작 완료 / 종료를 기본으로 한다.
* 제작 완료 이후 배송 대기 / 배송 중을 진행 중 주문의 세부 상태로 구분하고 도착 후 종료한다.
* 기한 상태는 정상 / 연체로 구분한다.
* 최종 결과는 정상 납품 / 지연 납품 / 직접 거절 / 자동 거절 / 주문 취소 / 최종 실패로 구분한다.
* 주요 요구 충족 여부는 최종 주문 결과가 아니라 평가 결과로 관리한다.
* D-0은 해당 날짜 영업 종료 전까지 수락 또는 납품할 수 있다는 의미이다.
* 마감일 영업 종료 후 미납 주문은 연체 / 지연 허용 기간 종료 후에도 미납이면 최종 실패 처리한다.
* 지연 허용 기간은 난이도별 데이터로 조정하며 Easy 4일 / Normal 3일 / Hard 2일을 1차 기준으로 사용한다.

### 주문 UI

* 탭은 수락 대기 / 진행 중 / 종료 주문 3개이다.
* 다른 화면에서 주문 화면으로 재진입하면 이전 상세·탭 선택을 유지하지 않고 수락 대기 목록과 닫힌 상세 상태로 초기화한다.
* 진행 중에는 제작 전 / 제작 중 / 배송 대기 / 배송 중 / 연체 주문을 표시한다.
* 제작 완료 후 배송 전 주문은 진행 중 탭에서 배송 대기로 표시한다.
* 배송 중 주문은 진행 중 탭에서 읽기 전용 배송 정보를 표시하고 도착 후 종료 탭으로 이동한다.
* 진행 중 주문은 제작 중 -> 배송 대기 -> 배송 중 순으로 정렬하고 같은 상태는 납품 기한이 가까운 순으로 표시한다.
* 종료 주문은 정상 납품 / 지연 납품 / 거절 / 자동 거절 / 주문 취소 / 최종 실패를 표시한다.
* UI에는 최근 종료 주문 20개만 최신순으로 표시하되 전체 기록은 결산을 위해 보존한다.
* 주문 난이도는 목록과 상세에 표시하지 않고 결산 표시 여부는 추후 결정한다.
* 주문 상세는 공용 패널 하나를 사용하고 제목 / 주문일 / 납품일 / 남은 기한 / 상태 / 최대 제작 코스트 / 주요 요구 / 희망 사항을 표시한다.
* 주문 상세의 주요 요구와 희망 사항은 씬에 미리 배치한 공용 정보 슬롯을 사용하고 조건 개수만큼 앞에서부터 활성화하며 남은 슬롯은 비활성화한다. 슬롯은 아이콘 / 항목 이름 / 요구 수량을 표시하고 화면 갱신마다 새로 생성하지 않는다.
* 주문 제목 / 특수 주문 여부와 조건 / 예상 보상은 상단 제목 구역에 표시하고 주문일 / 납품일 / 수락 또는 진행 상태는 주문 정보 구역에 표시한다.
* 남은 기한 문구는 수락 마감 / 납품 마감 / 최종 실패까지 남은 일수로 상태에 따라 변경한다.
* 수락 대기 상태는 수락 / 거절, Production은 제작 바로가기 / 주문 취소, 배송 대기는 배송 / 주문 취소 버튼을 사용한다.
* Production 상태 주문 상세는 선택한 주문 ID를 [CRAFT.md](CRAFT.md)의 제작 진입 흐름에 전달한다.
* Crafted 상태 주문을 선택하면 주문 상세를 생략하고 [DELIVERY.md](DELIVERY.md)의 배송 화면으로 바로 이동한다.
* 배송 성공 후에는 배송 패널과 기존 주문 상세를 닫고 종료 탭 목록만 표시한다.
* 수락 기한이 지나면 행동 버튼을 비활성화하고 영업 종료 시 자동 거절한다.
* 종료 주문 행동 버튼은 비활성화하고 상세 닫기 버튼은 별도로 유지한다.
* 주문 취소와 거절은 즉시 처리하지 않고 공용 경고 패널에서 페널티 / 파츠 미복구 / 제작물 폐기를 상태에 맞게 안내한다.
* 경고 패널은 주문 취소하기 또는 거절하기 / 돌아가기 문구를 사용한다.
* 주문 수는 탭에 따라 수락 대기 수 / 제한, 제작 완료 수 / 전체 진행 중 수, 최근 표시 종료 수 / 전체 종료 수로 표시한다.
* 주문 목록의 받은 주문과 상태별 수는 일일 제작 할당량과 별도로 유지한다.
* 서큐버스 주문 상담원을 고용하면 일일 신규 주문 범위의 최소치만 +1하고 최대치 5 / 수락 대기 빈자리 / 주문량 페널티 / 주간 보정은 기존 규칙을 유지한다.

### 주문량 페널티

* 페널티 적용 중 TopBar의 공용 툴팁 아이콘에 원인 / 감소량 / 남은 일수 / 예상 주문량을 표시한다.
* 기존 페널티에 새 페널티가 추가되면 적용 기간을 합산하되 남은 기간은 최대 14일로 제한한다.
* 일일 주문 감소량은 합산하지 않고 겹친 페널티 중 더 강한 감소량을 사용하며 서로 다른 원인은 복합 원인으로 표시한다.
* 진행률과 페널티 알림은 분리하고 목록 만석은 페널티와 다른 안내를 사용한다.
* 실제 다음 날 주문 생성 수에 페널티를 적용하는 연결은 DAY 단계에서 처리한다.
* 주간 평가 보정과 단기 페널티를 반영한 최종 신규 주문 수는 수락 대기 목록이 가득 찬 경우가 아니면 최소 1개를 보장하는 방향으로 1차 테스트한다.

### 특수 주문

* 특수 조건 종류는 없음 / 전체 파츠 개수 제한 / 목표 테마 / 제외 테마를 유지한다.
* Easy / Normal / Hard 난이도와 특수 주문 종류는 별도로 관리하며 하나의 주문에 난이도와 특수 규칙을 함께 적용할 수 있다.
* VIP 여부와 제작 제한 조건은 독립적으로 결정하므로 VIP 주문에도 개수 또는 테마 제한이 함께 붙을 수 있다.
* 제작 제한 조건은 전체 파츠 개수 제한 / 목표 테마 / 제외 테마 중 하나만 선택하며 한 주문에 복합 특수 조건을 생성하지 않는다.
* 전체 파츠 개수 제한은 주요 요구 / 희망 / 최소 제작 조건을 해결하는 최소 파츠 수에 `1~2`의 여유를 더해 생성한다.
* 목표 테마는 현재 해금 파츠와 주문 조건으로 활성화 가능한 테마 하나만 사용하고 완성 테마까지 요구하지 않는다.
* 제외 테마는 하나만 사용하며 해당 테마 파츠를 1개 포함한 것으로 위반 처리하지 않고 최종 제작물에서 해당 테마 시너지가 활성화됐을 때 위반으로 판정한다.
* 제외 테마 후보는 주요 요구·희망을 침범하지 않고 몸통 / 눈 / 코 / 입 최소 조건을 해결할 수 있을 때만 사용한다.
* 파츠 하나는 복수 테마를 가질 수 있고 테마 원본과 제작 시너지 판정은 [CRAFT.md](CRAFT.md)를 따른다.
* 전체 파츠 개수 제한 / 목표 테마 / 제외 테마 특수 주문은 B등급 이상 평가 누적 50회부터 해금한다.
* VIP 특수 주문은 A등급 이상 평가 누적 50회부터 해금하고 기본 가중치는 3으로 사용한다.
* 특수 주문은 별도 슬롯을 만들지 않고 같은 주문 슬롯을 사용하되 배경 스페셜 컬러 대신 특수 주문 아이콘과 전용 아이콘 연출로 구분한다. 일반 주문 슬롯으로 재사용될 때 아이콘과 실행 중인 연출을 반드시 초기화한다.
* 주문 상세에는 `특수: 전체 파츠 9개 이하` / `특수: 말랑 테마 목표` / `특수: 동글 테마 제외` 형식으로 표시한다.
* 목표 테마의 달성 판정과 점수 보정은 [CRAFT.md](CRAFT.md) / [DELIVERY.md](DELIVERY.md)에서 관리한다.
* 목표 테마 달성 결과는 제작 점수와 배송 등급을 통해 최종 주문 대금에 반영하며 별도 배송 배율을 추가하지 않는다.
* 2차 제작 보완의 `장착 후 제거 불가`는 일반 제작 규칙이 아니라 해당 규칙을 가진 특수 주문에서만 적용한다.
* 장착 후 제거 불가 주문에서도 배치한 파츠의 이동 / 크기 / 회전은 허용하고 제거 / 다른 파츠 교체는 금지하는 방향으로 검토한다.
* 생성 빈도는 특수 조건 없음이 가장 흔하고 목표 테마가 그다음, 전체 파츠 개수 제한과 제외 테마는 가끔 등장하는 방향만 유지하며 최종 가중치는 확정하지 않는다.

## PENDING

미구현 / 미결정

* 난이도 설정 데이터에 주요 요구 / 희망 / 최대 제작 코스트 / 수락·납품·지연 기간 1차 확정값을 반영한다.
* `OrderTitleData`에 확정 제목 풀을 입력하고 긴급 / VIP 분리와 최근 동일 제목 재추첨을 연결한다.
* 실제 다음 영업일 전환의 신규 주문 자동 호출은 DAY 연결 단계에서 처리하고 현재 확인용 날짜 입력의 호출은 이후 제거.
* 튜토리얼 상태 원본 구현 후 Normal 난이도 해금 조건 연결.
* PlayStateModel에 B등급 이상 / A등급 이상 평가 누적 수를 구분하고 OrderGeneratorModel의 특수 주문 해금 조건에 연결.
* 특수 조건 없음 / 목표 테마 / 전체 파츠 개수 제한 / 제외 테마의 최종 생성 가중치는 플레이 테스트 후 확정한다.
* 실제 파츠 데이터 전환 시 난이도별 고정 최대 제작 코스트와 주문 생성 재시도 방식에 맞춰 `OrderCostCalculator`의 고정 여유값 10 / 10단위 올림을 제거하고 현재 난이도 에셋을 함께 갱신한다.
* 장착 후 제거 불가 특수 주문의 몸통 교체 포함 여부 / 해금 조건 / 생성 가중치 / 안내 문구를 2차 제작 루프에서 확정.
* 모바일 실기기 입력 검증은 전체 UI 구현 이후 진행.
