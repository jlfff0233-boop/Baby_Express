# UPGRADE

## PURPOSE

정비 화면의 시설 / 연구 / 편의 / 직원 성장 시스템과 전체 현황을 관리한다.

* 실제 구현 완료 상태는 [DONE.md](../DONE.md)를 기준으로 확인한다.
* 최초 상품 구매와 상점 재고는 [SHOP.md](SHOP.md) / 인벤토리 용량은 [INVENTORY.md](INVENTORY.md) / 주문 접수 한도는 [ORDER.md](ORDER.md) / 제작 할당량과 급여 결산은 [DAY.md](DAY.md) / 배송 일정과 슬롯은 [DELIVERY.md](DELIVERY.md)를 따른다.
* 이 문서는 정비 항목의 획득 / 단계 / 효과 연결 / 자동화 허용 범위를 소유하고 실제 게임 규칙 계산은 담당 Model이 소유한다.

## CONFIRMED

확정 규칙

### 정비 분류

* 기존 업그레이드 화면의 표시 명칭은 `정비`로 사용한다.
* 정비 화면은 `전체 / 시설 / 연구 / 편의 / 고용` 순서로 표시한다.
* `전체`는 구매 가능한 정비 분류가 아니라 시설 / 연구 / 편의 / 고용의 현재 상태와 다음 진행 정보를 모아보는 UI 전용 탭이다.
* 실제 정비 분류는 `시설 / 연구 / 편의`이며 직원은 별도 고용 상태로 관리한다.
* 시설은 수치 성장 / 연구는 파츠·주문·정보 해금 / 편의는 기존 계산 결과의 가독성과 반복 확인 개선 / 직원은 플레이어가 선택을 끝낸 뒤의 업무 보조를 담당한다.
* 상점의 시설 분류와 정비의 시설 분류는 서로 다르며 상점 상품군은 `ProductType` / 정비 성장 분류는 `MaintenanceType`을 기준으로 독립 관리한다.
* 정비는 핵심 제작 선택을 없애는 전체 자동화가 아니라 운영 선택지와 편의성을 확장하는 성장 시스템이다.

### 획득과 업그레이드 흐름

* 상점에서 판매하는 정비 대상 상품은 최초 단계만 상점에서 구매한다.
* 최초 구매가 끝난 항목의 상위 단계는 정비 화면에서 자금을 지불해 올린다.
* 같은 단계나 같은 효과를 상점과 정비 화면 양쪽에서 중복 구매하지 않는다.
* 최초 구매에 성공한 항목은 영구 소유하며 별도 장착 / 해제 / 낮은 단계 교체는 사용하지 않는다.
* 상위 단계를 구매하면 이전 단계 효과를 영구적으로 대체하고, 서로 다른 효과의 정비는 동시에 적용한다.
* 전체 시설 장착 개수 제한은 두지 않는다.
* 구매 / 연구 / 이미 지급한 급여는 환불하지 않는다.

```text
상점에서 정비 상품 최초 구매
-> 정비 항목 해금 및 1단계 적용
-> 정비 화면에서 현재 효과 / 다음 단계 / 비용 / 조건 확인
-> 정비 화면에서 상위 단계 구매
-> 담당 Model에 새 최종 효과 적용
```

### 단계와 적용 기준

* 최대 단계 / 단계별 비용 / 단계별 효과 / 선행 조건 / 적용 시점은 데이터 에셋에서 조정한다.
* MVP 선행 조건은 누적 영업일 / 주간 영업 평가 / 선행 정비 단계만 사용한다.
* 업적 / 퀘스트 / 발견 / 복합 수집 조건은 확장 범위로 둔다.
* 용량 / 목록 한도 / 정보 공개처럼 당일 진행을 뒤집지 않는 효과는 구매 즉시 적용한다.
* 재입고 주기 / 일일 제작 할당량 / 신규 주문 후보처럼 영업일 생성·초기화에 영향을 주는 효과는 다음 적용 시점부터 반영한다.
* 이미 생성된 주문 / 이미 확정된 배송 일정 / 이미 보유한 아이템은 정비 구매로 삭제하거나 다시 계산하지 않는다.

### 시설 정비

#### 창고 정비

* 기본 인벤토리 용량은 50슬롯이다.
* 1차 단계안은 `50 -> 75 -> 100 -> 125 -> 150`으로 사용한다.
* 용량 증가는 구매 즉시 적용하며 기존 아이템과 스택은 유지한다.
* 시설 상품은 기존 규칙대로 인벤토리 용량을 사용하지 않는다.

#### 상점 최대 재고 정비

* 최대 재고 증가는 일반 재입고 간격 단축과 분리된 항목으로 둔다.
* MVP 효과 대상은 아기 파츠 상품이며 모든 상품군에 일괄 적용하지 않는다.
* 단계별 최종 증가량은 Lv.1 `+2` / Lv.2 `+4` / Lv.3 `+6` / Lv.4 `+8`을 사용한다.
* 최대 재고 증가 시 현재 재고를 무료로 채우지 않는다.
* 최종 최대 재고는 상품 기본 최대 재고 + 현재 정비 효과로 계산하며 단계를 올릴 때 누적 호출로 값이 중복 증가하지 않게 한다.

#### 일반 재입고 정비

* 일반 재입고 간격 단축은 최대 재고 증가와 분리된 항목으로 둔다.
* 단계당 재입고 간격 `-1일`, 최소 `3일`을 1차 기준으로 사용한다.
* 현재 진행 중인 재입고 주기를 소급 변경하지 않고 다음 일반 재입고 이후 새 주기부터 적용한다.
* 빠른 재입고의 횟수 / 비용에는 영향을 주지 않는다.

#### 주문 접수 정비

* 기본 수락 대기 한도는 5개 / 최종 최대 한도는 20개다.
* 1차 단계안은 `5 -> 8 -> 11 -> 14 -> 17 -> 20`으로 사용한다.
* 한도 증가는 즉시 적용하지만 빈자리에 당일 주문을 추가 생성하지 않고 다음 영업일 신규 주문 생성부터 사용한다.

#### 제작 정비

* 일일 제작 할당량 증가는 정비 성장에 포함한다.
* 할당량 증가는 난이도와 수익 규모를 함께 높이는 효과이므로 단순 편의가 아닌 제작 시설 성장으로 취급한다.
* 구매 당일 진행률과 자동 결산 조건을 바꾸지 않고 다음 영업일부터 적용한다.
* 기본 할당량 2건과 튜토리얼 첫날 1건은 [DAY.md](DAY.md)를 따르며 정비 단계별 최종 할당량은 Lv.1 `3` / Lv.2 `4` / Lv.3 `5`를 사용한다.

#### 배송 정비

* 새 배송의 소요일 단축은 기본 0일 / Lv.1 `-1일` / Lv.2 `-2일` / Lv.3 `-3일`을 사용하고 실제 배송 소요일은 최소 1일을 보장한다.

#### 시설 정비 가격

| 시설 | Lv.1 | Lv.2 | Lv.3 | Lv.4 | Lv.5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 인벤토리 최대 용량 | 400G | 800G | 1,300G | 2,000G | - |
| 파츠 최대 재고 | 600G | 1,100G | 1,800G | 2,700G | - |
| 일반 재입고 간격 | 700G | 1,300G | 2,100G | 3,000G | - |
| 대기 주문 한도 | 400G | 750G | 1,200G | 1,800G | 2,500G |
| 일일 제작 할당량 | 1,000G | 2,200G | 4,000G | - | - |
| 배송 소요일 단축 | 800G | 1,700G | 3,000G | - | - |

* 시설 정비 전체 누적 비용은 37,150G이다.

### 연구와 해금

* 연구 정비 상품은 상점에서 장비로 분류하고 최초 1회 구매한 뒤 상점에서 재구매하지 않으며 상위 단계는 정비의 연구 탭에서 올린다.
* 연구는 제작 성장 시스템이며 `파츠 연구 / 테마 연구` 두 종류로 구성한다.
* 연구는 영구 적용 / 장착·해제·ON/OFF 없음으로 통일하며 Hair / Wings / Tail / Horns는 최대 3단계, Claws는 최대 2단계이다.
* 단계가 오르면 이전 단계 효과를 유지한 채 파츠 연구는 신규 파츠를 추가 해금하고 테마 연구는 현재 단계의 최종 보너스로 교체한다.
* 잠긴 연구도 연구 탭에 표시하고 누적 영업일 / 주간 평가 / 선행 정비 단계 조건을 확인할 수 있게 한다.
* 복잡한 연구 트리보다 누적 영업일 중심의 단순한 진행을 우선하며 정확한 비용과 조건 수치는 데이터에서 조정한다.
* 파츠 연구는 `Hair / Wings / Tail / Claws / Horns` PartType별로 구성하고 `Body / Eye / Nose / Mouth / Arms / Legs` 기본 제작 타입은 연구로 잠그지 않는다.
* 파츠 연구의 각 단계에는 누적 목록이 아니라 해당 단계에서 새로 해금하는 파츠 ID만 저장하며 단계별 해금 수는 같지 않아도 된다.
* 파츠·상품 해금 상태의 런타임 원본은 `PlayStateModel`을 유지하고 상점 / 주문 생성 / 제작 / 카탈로그가 그 결과를 사용한다.
* 파츠 연구 효과는 즉시 적용해 상점 구매와 현재 주문 제작에 사용할 수 있게 하되 이미 생성된 주문은 바꾸지 않고 다음 영업일 신규 주문부터 생성 후보에 포함한다.
* Hard 주문은 11종 PartType이 모두 최소 1개 이상 해금된 뒤 후보가 되므로 전체 파츠 연구 진행 중 Hard 해금 시점이 지나치게 늦어지지 않게 배치한다.
* 테마 연구는 종족 테마가 아니라 성질 테마를 대상으로 구성한다. 현재 구현된 7종은 프로토타입으로 유지하고 최종 연구 목록은 [CRAFT.md](CRAFT.md)의 실제 파츠 기반 성질 테마 확정 후 함께 갱신한다.
* 테마 연구의 1차 단계값은 `Lv.1 +10 / Lv.2 +20 / Lv.3 +30`이며 누적 합산하지 않고 현재 적용 단계의 최종 보너스를 사용한다.
* 테마 연구 상태는 정비 단계가 소유하고 실제 테마 활성과 제작 점수 계산은 [CRAFT.md](CRAFT.md)의 `CraftReviewModel`이 담당한다.
* `InformationUnlock`은 편의 정보 표시 권한에 사용하며 이후 카탈로그 정보 연구도 같은 해금 구조를 재사용한다.
* 기본 기능을 잠가 두었다가 연구 상품으로 다시 판매하지 않는다.

#### 종족 해금

* 종족 해금은 누적 영업일과 누적 납품 수를 모두 만족하는 AND 조건을 사용하며 별도 골드 비용은 없다.

| 단계 | 조건 | 해금 종족 |
| --- | --- | --- |
| 초기 | Day 1 | Slime / Imp / Mushroom |
| 초반 | Day 7 이상 + 누적 납품 8회 | Ghost / Mandragora / Werewolf |
| 중반 | Day 14 이상 + 누적 납품 20회 | Goat / Kraken / Vampire |
| 후반 | Day 28 이상 + 누적 납품 45회 | Bicorn / Moth / Gargoyle |

* 종족 최초 해금 시 실제 존재하는 Body / Eye / Nose / Mouth / Arms / Legs 기본 파츠만 공개한다. Ghost는 Legs / Kraken은 Arms를 제외한다.
* 연구 확장 파츠는 `SpeciesUnlocked && ResearchLevelEnough`를 모두 만족해야 해금하며 연구를 먼저 달성한 뒤 종족이 열리면 충족 단계까지 즉시 반영한다.

#### 파츠 연구 단계와 가격

| 연구 | Lv.1 | Lv.2 | Lv.3 |
| --- | --- | --- | --- |
| Hair | Mandragora / Werewolf | Goat | Bicorn / Moth |
| Wings | Vampire | Moth | Gargoyle |
| Tail | Imp / Mandragora | Werewolf / Goat | Bicorn / Gargoyle |
| Horns | Imp / Goat | Bicorn | Gargoyle |
| Claws | Moth | Gargoyle | - |

* Hair / Tail / Claws 가격은 Lv.1 500G / Lv.2 1,200G / Lv.3 2,200G이며 Claws는 Lv.3을 사용하지 않는다.
* Wings / Horns 가격은 Lv.1 600G / Lv.2 1,400G / Lv.3 2,500G이다.
* Claws를 2단계로 조정한 Part Research 전체 누적 비용은 18,500G이다.

#### 테마 연구 가격

* 현재 성질 테마 7종은 동일하게 Lv.1 400G / Lv.2 900G / Lv.3 1,600G를 사용하고 테마 하나의 누적 비용은 2,900G이다.
* `+10 / +20 / +30`은 누적합이 아니라 해당 단계의 최종 효과값이다.

### 편의 기능

* 편의 기능은 해금 후 항상 적용하며 개별 ON / OFF는 두지 않는다.
* 정비는 정보 표시 권한만 소유하고 실제 값과 판정 결과는 기존 담당 Model에서 받는다.
* MVP 편의 기능은 주문 기한 임박 알림과 부족 파츠 표시 2종을 모두 구현한다.
* 편의 상품 ID는 `Convenience_OrderDeadlineAlert` / `Convenience_MissingPartsDisplay`, 실제 정보 해금 ID는 `Info_OrderDeadlineAlert` / `Info_MissingPartsDisplay`를 사용한다.
* 기한 임박은 D-1 / D-0인 수락 대기 / 제작 중 / 배송 대기 주문을 대상으로 주문 목록과 상세의 기존 기한 문구에 `[임박]`과 강조 색상을 적용한다.
* 부족 파츠는 주문 상세의 주요 요구 / 희망 문구에 현재 인벤토리 기준 부족 수량만 추가하고 미해금 상태에서는 기존 문구를 유지한다.
* 주문 마감 알림은 300G / 부족 파츠 표시는 500G의 단일 구매 가격을 사용한다.
* 시설 37,150G / Part Research 18,500G / Theme Research 20,300G / 편의 800G를 합친 전체 정비 누적 비용은 76,750G이다.
* 이미 기본 제공되는 사용 파츠 / 수량 / 현재 제작 코스트 / 테마 정보는 정비 상품으로 다시 판매하지 않는다.
* 2차 제작 보완에서도 기본 파츠 정보와 현재 `전체 / 시설 / 연구 / 편의 / 고용` 탭 구성을 유지한다.
* 2차 정보 해금은 기본 정보를 숨기는 방식이 아니라 테마별 정확한 점수 / 활성 테마 계산 / 상극과 복수 테마 감점 수치 / 예상 제작 점수 / 예상 등급·대금·수익처럼 더 정밀한 분석 정보를 단계적으로 추가하는 방향으로 검토한다.
* 생산 능력 / 정보 분석 / 운영 편의는 정비 탭을 교체하는 명칭이 아니라 2차 효과를 검토하는 설계 관점으로만 사용한다.

### 직원 기본 규칙

* 튜토리얼에서 무료 직원을 지급하지 않으며 초반에는 현재 기본 직접 배송을 사용한다.
* 첫 주간 결산 이후 배송 직원 `듀라한`을 해금하는 방향으로 진행한다.
* 직원은 정비 화면에서 플레이어가 직접 고용하고, 최초 고용비보다 낮은 정기 급여를 유지비로 사용하는 구조를 우선한다.
* 고용한 직원은 직원 카드의 `해고` 입력으로 직접 해고할 수 있으며 최초 고용비와 이미 지급한 주급은 반환하지 않는다.
* MVP 직원 대상은 듀라한 / 임프 / 고블린 / 서큐버스 / 그렘린 / 마녀 / 가고일 / 리치 8종이며 각 직원은 효과 하나만 가진다.
* `EmployeeData` 하나는 고유 직원 한 명을 의미하고 직원마다 카드 하나만 생성한다.
* 직원 이름은 영문 First / Last와 한글 표시 이름을 분리하고, 대화용 전신 초상화와 고용 카드용 크롭 초상화를 별도 참조한다.
* 각 직원은 고용 / 배송 배치 상태를 보관하며 미고용이면 `희망 업무`와 `고용`, 고용 상태면 `담당 업무`와 `해고`를 표시한다.
* 전체 최대 고용 수는 개별 직원 데이터가 아니라 `EmployeeModel`의 공용 고용 한도로 관리한다.
* 플레이어가 배송 화면에서 직원 배송을 선택하면 배치 가능한 직원 한 명을 자동 배정하며 제작 완료 즉시 자동 출발하지 않는다.
* 직원 태그 / 레벨 / 경험치 / 복수 직종 / 임시직 / 자동 업무 배정은 확장 범위이다.
* 급여는 일급이나 월급 대신 7일마다 주간 결산에서 지급하는 주급으로 통일한다.
* 주급은 직원 추가로 기대되는 주간 추가 이익의 약 35~50% 범위에서 테스트하고 정확한 금액은 데이터에서 조정한다.
* 주간 결산 시 직원별 `주급 × 미지급 고용 일수 ÷ 7`을 지급한다. 고용일과 해고일은 각각 근무일로 포함하고 같은 날 고용·해고하거나 재고용해도 하루는 한 번만 기록하며 해고한 직원의 미지급 고용 일수도 지급 전까지 유지한다.
* 직원별 비례 금액은 반올림하지 않고 모두 더한 뒤 최종 주급 합계만 1G 단위로 한 번 반올림한다.
* 주급은 부분 지급하지 않으며 자금이 부족하면 차감과 기록 없이 파산 처리하고 미지급 누적 / 평가 페널티 / 자동 퇴사는 MVP에서 사용하지 않는다.
* 직원 고용비와 주급은 기존 기타 지출에서 분리해 일일 / 주간 결산에 각각 표시하고 총지출과 순이익에 포함한다.

#### 직원 8종 1차 효과와 수치 확정안

| 직원 | 효과 | 해금 | 고용비 | 주급 |
| --- | --- | ---: | ---: | ---: |
| 듀라한 배송원 | 직원 배송 슬롯 +1 | 첫 주간 결산 / Day 7 | 800G | 300G |
| 임프 심부름꾼 | 빠른 재입고 비용 -25% | Day 10 | 900G | 320G |
| 고블린 재고 담당 | 인벤토리 판매율 50% -> 65% | Day 14 | 1,100G | 350G |
| 서큐버스 주문 상담원 | 일일 신규 주문 최소치 +1 | Day 21 | 1,400G | 400G |
| 그렘린 정비공 | 시설 / 편의 정비 Lv.2 이상 비용 -7% | Day 28 | 1,700G | 450G |
| 마녀 연구원 | 연구 정비 Lv.2 이상 비용 -10% | Day 35 | 1,900G | 500G |
| 가고일 운반원 | 일일 제작 할당량 +1 | Day 42 | 2,200G | 550G |
| 리치 회계사 | 전체 직원 주급 -10% | Day 49 | 2,400G | 600G |

* 위 수치는 데이터 에셋 작성에 사용하는 1차 확정안이며 실제 경제 시뮬레이션 후 재검수할 수 있다.
* 같은 고유 직원은 중복 고용하지 않고 전체 동시 고용 수는 현재 공용 설정값 3명을 1차 기준으로 사용하며 최대 고용 수 확장 정비는 추가하지 않는다.
* 서큐버스 효과는 기본 신규 주문 범위 `3~5`의 최소치만 `4`로 올리고 최대치는 유지하며 수락 대기 빈자리와 기존 페널티 / 주간 보정을 무시하지 않는다.
* 그렘린과 마녀의 할인은 상점 최초 구매가 아니라 정비 화면의 Lv.2 이상 비용에만 적용하고 서로 다른 대상 분류에 적용하므로 중첩 계산하지 않는다.
* 정비 할인은 `MaintenanceModel`의 공용 단계 비용 조회에서 현재 고용 직원 효과를 받아 계산하고 구매 가능 여부 / 실제 자금 차감 / 목록과 상세 표시가 모두 같은 최종 비용을 사용한다. 프레젠터와 뷰는 할인 비용을 다시 계산하지 않는다.
* 가고일 효과는 `BusinessDayModel`의 일일 제작 할당량 최종값에 더하고, 저장 데이터의 기존 직원 할당량 보너스와 호환되게 복구한다.
* 리치 효과는 직원별 비례 주급을 모두 합산한 전체 주급에 0.9 배율을 적용한 뒤 최종 금액을 한 번 반올림한다.

### 배송 직원과 배송 시설

* 직원과 시설이 같은 배송 효과를 중복 소유하지 않는다.
* 기본 직접 배송은 직원이 없어도 동시 배송 1건을 처리할 수 있다.
* 배송 직원 1명은 동시 배송 가능 수를 1건 늘린다.
* 배송 시설은 배송 소요일 단축을 담당하고 직원은 동시 배송 수를 담당한다.
* 직원과 시설 효과는 새로 출발하는 배송부터 적용하고 이미 확정된 배송 일정은 변경하지 않는다.
* 배송 출발 전 기존 배송 화면에서 담당 방식 / 예상 도착일 / 정상·지연 예상 / 예상 주문 대금을 확인하는 흐름을 유지한다.

#### 배송 예시

```text
직원 없음: 기본 직접 배송 슬롯 1건
듀라한 1명 고용: 동시 배송 2건
듀라한 2명 고용: 동시 배송 3건

배송 시설 강화: 위 슬롯 수는 그대로 / 새 배송의 소요일만 단축
```

### 자동화 허용 범위

* 허용: 기한 알림 / 부족 파츠 표시 / 필터와 정렬 / 제작 완료 후 배송 방식 선택과 직원 자동 배치 / 동시 배송 확장 / 배송 소요일 단축.
* 금지: 자동 주문 수락 / 자동 구매 / 최적 파츠 추천 / 자동 시너지 완성 / 아기 제작 전체 자동화 / 제작 완료 즉시 무조건 자동 출발.
* 핵심 재미인 발주 판단 / 주문 선택 / 파츠 조합 / 자유 배치는 플레이어가 직접 수행한다.

## SYSTEM_BOUNDARY

정비와 관련 시스템의 책임 경계

| 정비 효과 | 실제 적용 책임 | 적용 규칙 |

| 정비 단계·소유 상태 | `MaintenanceModel` | 항목 ID / 현재 단계 / 다음 비용 / 선행 조건 / 구매 결과 관리 |
| 파츠 최대 재고 | `ShopModel` / `ShopItemModel` | 파츠 상품에만 기본값 + 정비 효과 적용 / 무료 재고 충전 없음 |

| 파츠·상품 해금 상태 | `PlayStateModel` | 해금 원본을 한 곳에서 보관 |
| 테마 연구 단계·보너스 | `MaintenanceModel` / `CraftReviewModel` | 정비가 적용 단계를 소유하고 제작이 현재 최종 보너스로 점수 계산 |
| 주문 생성 후보 | `OrderGeneratorModel` | 다음 영업일부터 새 해금 결과 사용 |
| 배송 슬롯·소요일 | `DeliveryModel` | 직원 수와 시설 효과를 출발 전에 검증 / 일정 확정 후 불변 |
| 편의 정보 | 담당 Presenter / View | 기존 Model 결과를 표시만 하며 규칙 재계산 금지 |

| 자금·파산 | `PlayStateModel` / `BankruptcyModel` | 정비 구매와 주급 차감 결과를 공통 자금에 반영 |
| 직원 효과 상태 | `EmployeeModel` | 고용한 고유 직원과 현재 활성 효과 제공 |

* 정비 구매는 자금 / 최대 단계 / 선행 조건 / 현재 단계 / 담당 Model 적용 가능 여부를 모두 사전 검증한 뒤 자금 차감과 단계 상승을 하나의 결과로 처리한다.
* 효과 적용 실패 시 자금과 정비 단계가 부분 변경된 상태를 남기지 않는다.
* `MaintenancePresenter`는 View 입력과 상태 변경을 중재하고 `MaintenanceViewDataBuilder`가 정비 상태를 ViewData와 표시 문구로 변환하며 비용·효과·선행 조건을 직접 계산하지 않는다.
* `PlayScene`은 공용 Model 생성과 Presenter 의존성 연결만 담당한다.

## DATA_PLAN

정비 데이터와 런타임 구조 방향

* 정비 설정 데이터: 항목 ID / 시설 / 연구 / 편의 분류 / 표시 이름 / 최대 단계 / 단계별 비용 / 단계별 효과 / 선행 조건 / 적용 시점 / 최초 상점 상품 ID.
* 현재 `MaintenanceData`가 `PurchasableData`를 직접 상속하고 자체 상품 ID를 정비 ID로 사용하므로 별도 `MaintenanceProductData`나 연결 ID를 추가하지 않는다.
* 현재 프로토타입 정비 콘텐츠 범위는 시설 6종 / 파츠 연구 5종 / 성질 테마 연구 7종 / 편의 2종이며 성질 테마 최종 목록이 바뀌면 실제 데이터 수와 연구 항목도 함께 갱신한다.
* 정비 런타임 상태: 항목 ID / 소유 여부 / 현재 단계 / 다음 영업일 적용 예정 값.
* 직원 설정 데이터: 직원 ID / 종족 / 영문 First·Last / 한글 표시 이름 / 직종 / 대화용·고용용 초상화 / 고용비 / 주급 / 해금 종류와 값 / 효과 종류 하나 / 효과값 하나.
* `EmployeeModel`은 고용한 직원의 활성 효과를 효과 종류별로 제공하고 배송 슬롯 / 빠른 재입고 / 판매 / 주문 생성 / 정비 비용 / 제작 할당량 / 주급의 실제 수치 계산은 각 담당 Model이 수행한다.
* `EmployeeCsvImporter`는 직원 ID 기준으로 기존 에셋을 갱신하고 데이터 맵을 다시 구성하며, 초상화 키를 찾지 못하면 기존 Sprite 참조를 보존한다.
* 직원 저장은 기존 직원 ID와 고용 상태를 원본으로 유지하고 효과값을 중복 저장하지 않으며 복구 후 현재 직원 데이터에서 활성 효과를 다시 조회한다.
* 직원 런타임 상태: 직원 ID / 고용 여부 / 배송 배치 여부 / 미지급 고용 일수 / 마지막 고용 일수 기록 영업일. 같은 영업일의 중복 기록을 차단하고 주급 지급 성공 후 미지급 일수만 초기화한다.
* 직원 Model 런타임 상태: 마지막 주급 지급 영업일. 같은 주간 결산의 중복 지급을 차단한다.
* 화면 순서와 GameObject 이름은 저장 ID로 사용하지 않는다.
* 단계별 수치는 코드 상수가 아니라 데이터 에셋에 두고 담당 Model에는 현재 최종 적용값을 전달한다.
* 편의 기능은 항상 적용되므로 별도 활성 토글 상태를 저장하지 않는다.

## UI_PLAN

정비 화면 1차 구성

* 상단 탭은 `전체 / 시설 / 연구 / 편의 / 고용` 순서로 표시하고 같은 탭 바 안에서 전환한다.
* 화면 진입 시 `전체`를 기본으로 표시하며 전체 탭은 별도 구매 항목 없이 모든 정비 현황을 모아본다.
* 시설 / 연구 / 편의는 같은 목록 슬롯과 공용 상세 패널을 재사용하고 고용은 초상화가 보이는 직원 카드형 슬롯을 사용한다.
