# GUIDELINE

## PURPOSE

프로젝트 작업 방식과 협업 지침을 관리한다.

* 전체 진행 단계는 [ROADMAP.md](ROADMAP.md) / 게임 기획과 시스템 구조는 [DECISION.md](DECISION.md) / 미구현 작업은 [TODO.md](TODO.md) / 완료 상태는 [DONE.md](DONE.md) / 진행 차단 오류는 [ERROR.md](ERROR.md)에서 관리한다.
* 이 파일에는 게임 기능 자체가 아니라 작업 과정에서 계속 지켜야 하는 공통 기준만 기록한다.

## WORK_START

새 작업과 새 채팅 시작 기준

* 작업 시작 시 [GUIDELINE.md](GUIDELINE.md) -> [ROADMAP.md](ROADMAP.md)의 CURRENT_PHASE -> [TODO.md](TODO.md)의 CURRENT_TODO -> [DECISION.md](DECISION.md) -> 현재 작업과 연결된 System 파일 -> [DONE.md](DONE.md) 순서로 확인하고 오류 추적이 필요할 때 [ERROR.md](ERROR.md)를 추가 확인한다.
* System 파일은 현재 작업 하나만 기계적으로 고르지 않고 입력 / 출력 / 상태 변경이 연결된 다른 시스템 파일도 함께 확인한다.
* 메모만 믿고 진행하지 않고 현재 스크립트와 프로젝트 변경 사항을 먼저 확인한다.
* [DONE.md](DONE.md)에 없는 기능은 구현 완료로 추정하지 않고 실제 코드를 확인한다.
* DECISION / System / DONE / 현재 코드 / 사용자 설명이 충돌하면 임의로 하나를 선택하지 않고 충돌 내용을 사용자에게 확인한다.
* 계획 / 검토 / 설명 요청에는 파일을 수정하지 않고 실제 수정 요청이 있을 때만 변경한다.
* 사용자가 대기를 요청하면 추가 조사나 수정을 진행하지 않는다.
* 이전 채팅의 맥락을 추측해 복원하지 않고 이 파일과 현재 프로젝트 상태를 기준으로 작업을 이어간다.
* 시스템 작업 종료 시 담당 System 파일의 CONFIRMED / PENDING을 갱신하고 실제 완료 사항은 [DONE.md](DONE.md) / 시스템 단계 변경은 [ROADMAP.md](ROADMAP.md)에 반영한다.
* 중요한 시스템 결정은 작업 종료까지 미루지 않고 확정된 시점에 담당 System 파일에 즉시 기록한다.

## COMMUNICATION

사용자와의 협업 기준

* 존댓말을 사용하고 결과와 핵심 내용을 먼저 간결하게 설명한다.
* 질문한 내용과 제시된 외부 의견을 구분하고 사용자가 요청하지 않은 실행으로 확대하지 않는다.
* 계획 요청에는 당장 해야 할 작업부터 우선순위대로 제시하고 자잘한 내부 작업을 별도 단계로 부풀리지 않는다.
* 코드 요청이 아니면 임의로 코드를 제시하지 않는다.
* 정보가 부족하거나 프로젝트 상태로 확인할 수 없는 내용은 추측하지 않고 필요한 정보를 요청한다.
* 사용자가 정한 용어와 명칭을 우선 사용하고 새 명칭을 제안할 때는 기존 명칭과 역할 차이를 함께 설명한다.
* 작업 시간은 사용자 직접 작성 / 코드 제공 후 복사 / 직접 수정 대행 중 어떤 방식을 전제로 하는지 구분해 산정한다.

## CODE_STYLE

코드 작성과 표시 기준

* 현재 파일의 줄바꿈 / BOM 포함 UTF-8 인코딩 / 공백 / 괄호 / 주석과 서머리 말투를 유지한다.
* 클래스와 함수에는 한글 summary / 주요 코드에는 기능을 바로 파악할 수 있는 한글 주석을 사용한다.
* 별도 접근 제한자가 필요하지 않은 private 멤버에는 private을 표기하지 않는다.
* 전체 파일 대신 변경된 부분만 보여 주고 기존 코드와 수정 코드의 핵심 차이를 짧게 설명한다.
* 실제 스크립트에서는 필드 / 프로퍼티 / 이벤트 다음에 생성자 / 초기화 함수 / Unity 생명주기를 상단에 배치한다.
* 실제 스크립트의 일반 함수는 호출하는 함수를 먼저 배치하고 해당 함수가 호출하는 내부 보조 함수는 아래에 배치한다.
* 같은 책임의 함수는 region으로 묶되 생성자 / 초기화 함수 / Unity 생명주기를 파일 하단으로 내리지 않는다.
* 답변에서 여러 코드 조각을 안내할 때만 사용자가 존재 여부를 혼동하지 않도록 필요한 변수와 피호출 요소를 먼저 소개하고 실제 스크립트 배치 순서와 구분해 설명한다.
* 함수명과 변수명은 지나치게 길거나 역할이 불분명하지 않게 현재 프로젝트 용어에 맞춘다.
* 이벤트 이름에는 이벤트 자체가 요청을 의미하는 경우 Requested를 반복해서 붙이지 않는다.
* `PlayScene`에서 생성과 전달을 보장하는 생성자 의존성은 별도 `ArgumentNullException` 검증 없이 직접 대입하며, 같은 위치의 null 오류를 옮기기만 하는 방어 코드를 추가하지 않는다.

## IMPLEMENTATION

수정과 구현 행동 기준

* 새 기능을 제안하기 전에 기존 Model 책임 / 기존 Presenter 중재 / 신규 Model 필요 여부 순서로 검토한다.
* 새 스크립트와 에셋 생성은 사용자 요청 범위에서만 진행하고 사용자가 직접 생성하기로 한 파일은 대신 만들지 않는다.
* 단순 이름 변경도 직렬화 에셋과 참조 영향을 먼저 확인하고 사용자 승인 범위 안에서 수정한다.
* 씬 / 프리팹 / YAML은 직접 수정하지 않고 Unity 메타 파일(.meta)은 생성 / 수정 / 삭제하지 않는다.
* 사용자 작업과 관련 없는 변경 사항은 수정하거나 되돌리지 않는다.
* 코드 간소화는 중복 검증 / 도달할 수 없는 방어 코드 / 의미 없는 래퍼 / 반복 로그를 우선 대상으로 한다.
* Model의 게임 규칙 검증 / View 사용자 입력 검증 / 여러 Model을 변경하는 처리의 사전 검증과 실패 시 원상 유지는 제거하지 않는다.
* 코드 줄 수를 줄이기 위해 역할 분리나 실패 처리 기준을 훼손하지 않는다.
* 수정 후 변경 파일 / 핵심 변경 / 확인 결과 / 발생 가능한 사이드 이펙트만 보고한다.

## REFERENCE

레퍼런스와 범위 제안 기준

* 새로운 시스템을 제안하기 전에 필요한 이유와 기존 시스템으로 해결하기 어려운 이유를 설명한다.
* 기존 시스템으로 부족하면 [DECISION.md](DECISION.md)의 메인 레퍼런스 범위에서 먼저 해결 방법을 검토한다.
* 제안 기능은 MVP / 확장 / 보류 범위를 구분하고 더 적은 구현 비용으로 같은 목적을 달성할 수 있으면 축소안을 함께 제시한다.
* 레퍼런스 기능을 그대로 복제하지 않고 Baby Express의 핵심 루프와 개발 기간에 맞춰 변형한다.

## MEMO_RULE

메모 기록 기준

* 프로젝트 공식 메모는 `Docs/Memo`의 Markdown 문서이며 다른 위치의 TXT 또는 백업 문서는 작업 기준으로 사용하지 않는다.
* 새 작업과 메모 갱신은 `.md` 파일만 대상으로 하며 같은 내용의 TXT 사본을 함께 관리하지 않는다.
* [ROADMAP.md](ROADMAP.md)에는 전체 MVP 진행 단계 / 시스템별 상태 / 현재 작업 위치 / 대략적인 전체 진행률만 기록한다.
* [DECISION.md](DECISION.md)에는 프로젝트 전역 기획 / 공통 구조 / 시스템 경계 / 전체 범위 / System 파일 색인만 기록한다.
* System 폴더에는 시스템별 확정 규칙 / 흐름 / MVP 책임 / 데이터 / UI / 예시 / 미구현 / 미결정 / 확장 범위를 기록한다.
* 시스템 파일은 처음부터 모두 만들고 미정인 시스템도 현재 초기 기획 / 미정 / 보류 상태를 기록해 대화 압축으로 인한 유실을 막는다.
* System 파일은 메인 시스템 단위로만 분리하고 장바구니 / 구매 / 시너지 / 평가 / 결산 / 직원 같은 하위 시스템은 담당 메인 파일의 상단 CONTENTS와 본문에서 관리한다.
* System 파일 상단에는 줄 번호 없이 하위 시스템 목차를 두어 코딩 작업 중 필요한 항목을 바로 찾을 수 있게 한다.
* [TODO.md](TODO.md)에는 현재 최우선 작업 / 다음 시스템 진행 순서 / 시스템 간 선행 작업 / 통합 검증만 기록한다.
* [DONE.md](DONE.md)에는 시스템 단위 구현 완료와 중요한 검증 결과만 기록한다.
* [ERROR.md](ERROR.md)에는 개발 진행을 실제로 막았고 원인 추적에 시간이 걸린 오류만 기록한다.
* [GUIDELINE.md](GUIDELINE.md)에는 작업 방식 / 코드 작성 / 협업 / 메모 관리처럼 여러 시스템에 반복 적용되는 지침만 기록한다.
* [ROADMAP.md](ROADMAP.md)의 진행률과 시스템 상태는 세부 기능 하나마다 갱신하지 않고 시스템 단계가 바뀔 때 갱신한다.
* 사소한 이름 변경 / 임시 디버그 사용 여부 / 경고 0개 / 단순 참조 연결은 메모에 기록하지 않는다.
* 같은 내용을 여러 메모에 중복 기록하지 않고 성격에 맞는 파일 하나를 단일 원본으로 사용한다.
* 전역 규칙은 [DECISION.md](DECISION.md) / 시스템별 확정 규칙은 담당 System 파일의 CONFIRMED / 실제 구현은 현재 코드와 [DONE.md](DONE.md) / 미정 사항은 System 파일의 PENDING을 기준으로 구분한다.
* 시스템 간 겹치는 규칙은 실제 계산이나 상태를 소유한 시스템 파일 하나에만 상세히 기록하고 다른 파일에서는 담당 파일을 참조한다.
* 같은 성격의 짧은 항목은 세로로 길게 나열하지 않고 "/"로 병렬 정리한다.
